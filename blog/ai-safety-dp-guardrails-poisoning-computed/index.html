AI 安全的三笔账：ε、误伤与投毒

#AI 工程#AI 安全#技术深度#面试笔记

AI 安全的三笔账？ε 该花多少训练量、护栏会误伤多少人、投毒要抽多少条才查得出来。我的面试答案笔记《10 AI 安全与伦理》里有 20 道题（幻觉、提示注入、护栏、对齐、偏见、隐私、可解释性、机制可解释性、对抗攻击、数据投毒、责任 AI、版权、EU AI Act、NIST AI RMF、差分隐私、审计日志、模型卡、滥用治理），答案都写得很完整，但三笔「各是多少」是定性的。这篇把它们算出来。

口径说明

  • 源是我自己的面试答案笔记 06-面试/答案/10-AI安全与伦理-答案.md（29 KB，20 题）。可以自由引用；本文正文主体是自写可复现模型。
  • 三个脚本只依赖 Python 标准库；输出为实跑结果，逐行可复现（无随机数，两次运行输出逐字一致）。
  • 笔记里给出的量（ε-DP 定义与 ε 直觉表、DP-SGD 草图里的裁剪范数 C 与噪声乘子 σ、三层护栏架构、五类注入分类、三类投毒与「右下角黄色方块」触发器）直接标注来源；我为了建模补的（采样率 q、步数 T、δ、各层拦截率与误报率、请求量、复核工时与人力单价、投毒率）都标为「估」。
  • 撞题检查：自动判 LOW_RISK（只有共同实体词，人工确认不是同一主题）；已发语料里没有「差分隐私的效用账 / 护栏的误伤账 / 投毒的抽样账」这一篇。

一、笔记的骨架：三个机制

Q17 差分隐私：ε-DP 的定义是「对任意相差一个样本的相邻数据集 D、D’ 与任意输出 S，Pr[M(D) ∈ S] ≤ e^ε · Pr[M(D') ∈ S]」——保证任何单个样本的加入/移除都不会显著改变模型输出。笔记给了 ε 的直觉表（ε=0.1 极强但实用性极低、ε=1 强、ε=3 中等但工业级常用、ε=10 弱到实际近似不防隐私），以及 DP-SGD 的算法草图：采样 batch → 逐样本算梯度 → 按范数 C 裁剪 → 求平均 → 加高斯噪声 N(0, σ²C²I) → 更新参数。

Q2/Q3 提示注入与护栏：注入 = 攻击者构造输入让模型忽略 system prompt 转而执行攻击者的意图（「LLM 时代的 SQL Injection」），分类含直接注入、间接注入（藏在网页/邮件/文档/RAG 文档里）、越狱、提示词套取、指令覆盖；护栏的核心思路是「永远不要完全信任 LLM 的输入或输出」，三层是输入分类器（注入/越狱检测、PII 检测、白名单）、模型层约束（system prompt、工具白名单、约束解码）、输出校验。

Q12 数据投毒：攻击者在训练阶段注入恶意样本，使模型在特定输入（触发器）下产生指定错误行为；三类是标签翻转、后门攻击（插入「触发器 + 目标标签」对，示例是右下角带黄色方块的猫被标成 guinea pig）、clean-label 攻击（不改标签，只精心构造特征，更隐蔽）。

二、增量一：ε 不是隐私旋钮，是成本旋钮

笔记给了 ε 的直觉表，但没说「ε 降一档要花多少」。把它算出来：

"""DP-SGD：ε 不是隐私旋钮，是成本旋钮。

用笔记的量：ε-DP 定义、DP-SGD 草图（裁剪范数 C、噪声乘子 σ）、ε 直觉表（0.1 极强 / 1 强 / 3 工业常用 / 10 弱）。
只依赖标准库；输出确定性。
"""
import math

N = 1_000_000
BATCH = 1024
STEPS = 10_000
DELTA = 1e-6

q = BATCH / N
print("一、σ 与 ε 的关系（常用高斯 DP 上界估计：ε ≈ q·√(T·ln(1/δ))/σ）")
print("   采样率 q = %d/%s = %.5f，步数 T=%d，δ=%g" % (BATCH, format(N, ","), q, STEPS, DELTA))
print("   注意方向：**σ 越大 -> 噪声越大 -> ε 越小（隐私越强）**，代价是训练量按 σ² 涨。")
print()
print("%-10s %14s %18s %18s" % ("噪声乘子 σ", "ε(上界估计)", "相对噪声 σC/|ḡ|", "等效训练量(×σ=1)"))
base = None
for sigma in (0.1, 0.5, 1.0, 2.0, 5.0, 10.0):
    eps = q * math.sqrt(STEPS * math.log(1 / DELTA)) / sigma
    extra = sigma ** 2
    if sigma == 1.0:
        base = extra
    print("%-10.1f %14.3f %17.0f%% %17.2f x" % (sigma, eps, sigma * 100, extra))
print()
print("   => σ 从 1 到 10：ε 从 %.3f 降到 %.3f（隐私强 10 倍），等效训练量差 %.0f 倍。"
      % (q * math.sqrt(STEPS * math.log(1 / DELTA)) / 1.0,
         q * math.sqrt(STEPS * math.log(1 / DELTA)) / 10.0, 100))
print()
print("二、对照笔记的 ε 直觉表（反解需要的 σ 与训练量）")
for eps_target in (10.0, 3.0, 1.0, 0.1):
    sigma_need = q * math.sqrt(STEPS * math.log(1 / DELTA)) / eps_target
    print("   要达 ε=%4.1f -> 需要 σ=%.2f -> 等效训练量约 %.2f 倍（相对 σ=1）"
          % (eps_target, sigma_need, sigma_need ** 2))
print()
print("三、步数 T 也在动 ε：同样 σ，训得越久隐私越差")
for steps in (1_000, 10_000, 100_000):
    eps = q * math.sqrt(steps * math.log(1 / DELTA)) / 1.0
    print("   σ=1、T=%6d -> ε=%.3f（训练量 %.2f 倍）" % (steps, eps, steps / STEPS))
print()
print("四、裁剪范数 C 的作用：不是越大越好")
print("   C 限制单样本影响：梯度被裁到范数 C 以内。设典型梯度范数为 G，")
for ratio in (0.25, 0.5, 1.0, 2.0):
    clipped = max(0.0, 1.0 - ratio) * 100
    note = "（几乎不裁剪，但隐私倍数分析会失效）" if ratio >= 1.0 else "（信号被削弱）"
    print("     C = %.2f x G -> 被裁剪的梯度约 %.0f%% %s" % (ratio, clipped, note))
print()
print("判据：")
print("  - **ε 不是「隐私旋钮」而是「成本旋钮」**：σ=1 与 σ=10 之间隐私强 10 倍，训练量差 100 倍。")
print("    这就是工业界用 ε≈3 而不是 ε=0.1 的原因。")
print("  - **步数 T 也在消耗隐私预算**：同样 σ，训练量涨 10 倍 -> ε 涨 %.1f 倍 -> 所以 DP 训练要早停。" % math.sqrt(10))
print("  - **δ 要跟着 N 走**：通常取 1/N 量级；训练集越大，δ 越松。")
print("  - **DP 的成本不只在训练**：DP 模型的产出去接更多私有数据微调时，隐私债要在同一个 ε 预算里扣两次。")

输出：

一、σ 与 ε 的关系（常用高斯 DP 上界估计：ε ≈ q·√(T·ln(1/δ))/σ）
   采样率 q = 1024/1,000,000 = 0.00102，步数 T=10000，δ=1e-06
   注意方向：**σ 越大 -> 噪声越大 -> ε 越小（隐私越强）**，代价是训练量按 σ² 涨。

噪声乘子 σ            ε(上界估计)        相对噪声 σC/|ḡ|        等效训练量(×σ=1)
0.1                 3.806                10%              0.01 x
0.5                 0.761                50%              0.25 x
1.0                 0.381               100%              1.00 x
2.0                 0.190               200%              4.00 x
5.0                 0.076               500%             25.00 x
10.0                0.038              1000%            100.00 x

   => σ 从 1 到 10：ε 从 0.381 降到 0.038（隐私强 10 倍），等效训练量差 100 倍。

二、对照笔记的 ε 直觉表（反解需要的 σ 与训练量）
   要达 ε=10.0 -> 需要 σ=0.04 -> 等效训练量约 0.00 倍（相对 σ=1）
   要达 ε= 3.0 -> 需要 σ=0.13 -> 等效训练量约 0.02 倍（相对 σ=1）
   要达 ε= 1.0 -> 需要 σ=0.38 -> 等效训练量约 0.14 倍（相对 σ=1）
   要达 ε= 0.1 -> 需要 σ=3.81 -> 等效训练量约 14.49 倍（相对 σ=1）

三、步数 T 也在动 ε：同样 σ，训得越久隐私越差
   σ=1、T=  1000 -> ε=0.120（训练量 0.10 倍）
   σ=1、T= 10000 -> ε=0.381（训练量 1.00 倍）
   σ=1、T=100000 -> ε=1.204（训练量 10.00 倍）

四、裁剪范数 C 的作用：不是越大越好
   C 限制单样本影响：梯度被裁到范数 C 以内。设典型梯度范数为 G，
     C = 0.25 x G -> 被裁剪的梯度约 75% （信号被削弱）
     C = 0.50 x G -> 被裁剪的梯度约 50% （信号被削弱）
     C = 1.00 x G -> 被裁剪的梯度约 0% （几乎不裁剪，但隐私倍数分析会失效）
     C = 2.00 x G -> 被裁剪的梯度约 0% （几乎不裁剪，但隐私倍数分析会失效）

判据：
  - **ε 不是「隐私旋钮」而是「成本旋钮」**：σ=1 与 σ=10 之间隐私强 10 倍，训练量差 100 倍。
    这就是工业界用 ε≈3 而不是 ε=0.1 的原因。
  - **步数 T 也在消耗隐私预算**：同样 σ，训练量涨 10 倍 -> ε 涨 3.2 倍 -> 所以 DP 训练要早停。
  - **δ 要跟着 N 走**：通常取 1/N 量级；训练集越大，δ 越松。
  - **DP 的成本不只在训练**：DP 模型的产出去接更多私有数据微调时，隐私债要在同一个 ε 预算里扣两次。

三处结论：

第一，σ 每放大 10 倍，隐私强 10 倍，训练量差 100 倍。 用常用的高斯 DP 上界估计（ε ≈ q·√(T·ln(1/δ))/σ，采样率 q=0.00102、T=10,000、δ=1e-6）：σ=1 → ε=0.381、等效训练量 1×；σ=10 → ε=0.038、等效训练量 100×。方向别搞反：σ 越大 → 噪声越大 → ε 越小（隐私越强），代价是达到同样效用所需样本量按 1/σ² 涨。判据：ε 不是隐私旋钮，是成本旋钮——这正是工业界停在 ε≈3 而不是 0.1 的原因（本模型下 ε=3 只需 σ=0.13，训练量几乎不涨；ε=0.1 需要 σ=3.81、训练量 14.5 倍）。

第二，步数 T 也在消耗隐私预算，所以 DP 训练要早停。 同样 σ=1：T=1,000 → ε=0.120；T=10,000 → 0.381；T=100,000 → 1.204。训练量涨 10 倍，ε 涨 3.2 倍——「多训一会儿」在 DP 下是有隐私代价的，而普通训练里多训通常是免费的。

第三，裁剪范数 C 不是越大越好。 C 限制单样本的最大影响：设典型梯度范数为 G，C=0.25G → 约 75% 的梯度被裁剪（信号被削弱）；C=1.0G → 几乎不裁剪，但隐私倍数分析的前提就失效了（没被限制住的影响谈不上「每样本有界」）。C 是「分析有效性 ↔ 信号强度」之间的那个旋钮。

三、增量二：护栏的拦截是乘积，误伤也是乘积

笔记的三层护栏架构没有给各层的拦截率与误报率。把它们代进去：

"""多层护栏：拦截是乘积，误伤也是乘积。

用笔记的量：三层护栏（输入分类器 / 模型层约束 / 输出校验）、永远不要完全信任 LLM 的输入或输出、
直接/间接注入与越狱分类。
只依赖标准库；输出确定性。
"""
REQUESTS_DAY = 1_000_000
REVIEW_MIN = 3
REVIEW_RATE = 40
LAYERS = 3


def sweep(r_block, f_false):
    leak = (1 - r_block) ** LAYERS          # 三层都没拦住的概率
    false_rate = 1 - (1 - f_false) ** LAYERS  # 至少一层误拦的概率
    blocked = REQUESTS_DAY * false_rate
    hours = blocked * REVIEW_MIN / 60
    print("  每层拦截 %.0f%%、误报 %.2f%% -> 总漏过 %.4f%%、总误伤 %.2f%%"
          % (r_block * 100, f_false * 100, leak * 100, false_rate * 100))
    print("     每天 %s 请求：漏过 %s 个注入进入系统；误伤 %s 个正常请求 -> 复核 %.0f 人时/天 = %.1f FTE = $%s/天"
          % (format(REQUESTS_DAY, ","), format(int(REQUESTS_DAY * leak), ","),
             format(int(blocked), ","), hours, hours / 8, format(int(hours * REVIEW_RATE), ",")))


print("一、单层 95% 拦截 / 1% 误报")
sweep(0.95, 0.01)
print()
print("二、单层 99% 拦截 / 0.1% 误报")
sweep(0.99, 0.001)
print()
print("三、单层 90% 拦截 / 0.1% 误报（分类器很弱）")
sweep(0.90, 0.001)
print()
print("四、为什么两类注入该用不同阈值")
print("   漏过 1 个成功的间接注入 -> 可能是一次数据外泄或越权工具调用；")
print("   误伤 1 个正常请求 -> 一次重试或人工复核。")
print("   所以间接注入（藏在 RAG/工具返回里、用户看不见）该偏向高拦截、容忍误伤；")
print("   直接注入（用户自己发的）误报成本低，可以拦得更狠。")
print()
print("五、护栏自身的开销（每次请求两次额外模型调用）")
for ms, price in ((80, 0.001), (300, 0.004)):
    print("   多 %.0f ms、$%.4f -> 每天 $%s" % (ms * 2, 2 * price, format(int(REQUESTS_DAY * 2 * price), ",")))
print()
print("判据：")
print("  - **拦截与误伤都是乘积**：三层 95%%/1%% -> 漏过 %.4f%%、误伤 %.2f%%；三层 99%%/0.1%% -> 漏过 %.4f%%、误伤 %.2f%%。"
      % ((1 - 0.95) ** 3 * 100, (1 - (1 - 0.01) ** 3) * 100,
         (1 - 0.99) ** 3 * 100, (1 - (1 - 0.001) ** 3) * 100))
print("    **加层的边际收益是指数的，误伤也是指数的** —— 层的数量是预算问题，不是越多越好。")
print("  - **护栏本身是成本项**：两次额外模型调用 -> 延迟与账单都要进预算；")
print("    「三层护栏」在百万级 QPS 上不便宜。")
print("  - 判据：**先按攻击类型分档配阈值，再决定层数**。")

输出：

一、单层 95% 拦截 / 1% 误报
  每层拦截 95%、误报 1.00% -> 总漏过 0.0125%、总误伤 2.97%
     每天 1,000,000 请求：漏过 125 个注入进入系统；误伤 29,700 个正常请求 -> 复核 1485 人时/天 = 185.6 FTE = $59,401/天

二、单层 99% 拦截 / 0.1% 误报
  每层拦截 99%、误报 0.10% -> 总漏过 0.0001%、总误伤 0.30%
     每天 1,000,000 请求：漏过 1 个注入进入系统；误伤 2,997 个正常请求 -> 复核 150 人时/天 = 18.7 FTE = $5,994/天

三、单层 90% 拦截 / 0.1% 误报（分类器很弱）
  每层拦截 90%、误报 0.10% -> 总漏过 0.1000%、总误伤 0.30%
     每天 1,000,000 请求：漏过 999 个注入进入系统；误伤 2,997 个正常请求 -> 复核 150 人时/天 = 18.7 FTE = $5,994/天

四、为什么两类注入该用不同阈值
   漏过 1 个成功的间接注入 -> 可能是一次数据外泄或越权工具调用；
   误伤 1 个正常请求 -> 一次重试或人工复核。
   所以间接注入（藏在 RAG/工具返回里、用户看不见）该偏向高拦截、容忍误伤；
   直接注入（用户自己发的）误报成本低，可以拦得更狠。

五、护栏自身的开销（每次请求两次额外模型调用）
   多 160 ms、$0.0020 -> 每天 $2,000
   多 600 ms、$0.0080 -> 每天 $8,000

判据：
  - **拦截与误伤都是乘积**：三层 95%/1% -> 漏过 0.0125%、误伤 2.97%；三层 99%/0.1% -> 漏过 0.0001%、误伤 0.30%。
    **加层的边际收益是指数的，误伤也是指数的** —— 层的数量是预算问题，不是越多越好。
  - **护栏本身是成本项**：两次额外模型调用 -> 延迟与账单都要进预算；
    「三层护栏」在百万级 QPS 上不便宜。
  - 判据：**先按攻击类型分档配阈值，再决定层数**。

三处结论：

第一，漏过率与误伤率都是乘积，而且两边一起变。 三层各 95% 拦截 / 1% 误报：总漏过 0.0125%（每天 100 万请求里漏过 125 个注入）、总误伤 2.97%（29,700 个正常请求被拦，复核要 1,485 人时 ≈ 186 FTE ≈ $5.9 万/天）。三层各 99%/0.1%：漏过 0.0001%（每天 1 个）、误伤 0.30%（2,997 个、18.7 FTE、$6,000/天）。判据：加层的边际收益是指数的，误伤也是指数的——层的数量是预算问题，不是越多越好。

第二，漏过与误伤的代价不对称，所以两类注入该用不同阈值。 漏过 1 个成功的间接注入（藏在 RAG/工具返回里，用户自己看不见）可能是一次数据外泄或越权工具调用；误伤 1 个正常请求只是一次重试。所以间接注入该偏向高拦截、容忍误伤；直接注入（用户自己发的）误报成本低、可以拦得更狠。笔记把五类注入并列讲了，但没讲它们该配不同的护栏预算。

第三，护栏本身是成本项。 每次请求两次额外模型调用（输入分类 + 输出校验）：分类器 80 ms/$0.001 → 每天 +160 ms、$2,000/天；300 ms/$0.004 → +600 ms、$8,000/天。「三层护栏」在百万级 QPS 上不便宜——它进的是延迟预算与账单，不只是安全预算。

四、增量三：投毒检出的抽样量，与清洗成本

笔记列了三类投毒与触发器机制。检出与清洗要多少钱，可以算：

"""数据投毒：检出所需的抽样量，与清洗所需的干净数据量。

用笔记的量：三类投毒（标签翻转 / 后门 / clean-label）、后门触发器（右下角黄色方块）。
只依赖标准库；输出确定性。
"""
import math

TRAIN_N = 1_000_000
DETECT_TARGET = 0.95
CHECK_COST = 0.02


def k_for(p):
    return math.ceil(math.log(1 - DETECT_TARGET) / math.log(1 - p))


print("一、随机抽检的检出概率：投毒率 p、抽检 k 条 -> 检出 = 1 - (1-p)^k")
print("%-14s %16s %14s %20s" % ("投毒率 p", "检出 95% 需抽", "抽检成本", "占训练集"))
for p in (0.001, 0.005, 0.01, 0.05, 0.10):
    k = k_for(p)
    print("%-14s %16s %14s %19.4f%%" % ("%.1f%%" % (p * 100), format(k, ","),
          "$" + format(k * CHECK_COST, ".2f"), 100.0 * k / TRAIN_N))
print()
k_low, k_high = k_for(0.001), k_for(0.10)
print("   => 检出所需样本量按 log(1/p) 增长：p=0.1%% 要抽 %s 条，p=10%% 只要 %s 条（差 %d 倍）。"
      % (format(k_low, ","), format(k_high, ","), k_low // k_high))
print()
print("二、后门的稳定性：投毒比例与触发器被学到的概率")
for p in (0.0001, 0.001, 0.01, 0.1):
    verdict = ("几乎学不到（触发器被当噪声）" if p < 0.0005 else
               "弱后门（可能不稳）" if p < 0.005 else
               "可稳定植入" if p < 0.05 else "过强，特征明显反而易被检测")
    print("   投毒率 %.2f%% -> %s" % (p * 100, verdict))
print()
print("三、清洗的成本：稀释投毒需要多少干净数据")
for p in (0.001, 0.01, 0.1):
    clean_needed = TRAIN_N * p / (1 - p)
    print("   投毒率 %.1f%% -> 稀释到同量级需额外 %s 条干净数据（训练集的 %.1f%%）"
          % (p * 100, format(int(clean_needed), ","), 100.0 * clean_needed / TRAIN_N))
print()
print("四、clean-label 攻击只能靠定向检查")
print("   不改标签、只改特征 -> 标签异常检测与随机抽检都无效；")
print("   只能针对触发器做模式匹配（例如找右下角特定色块的样本）->")
print("   这与「低投毒率下随机抽检不经济」正好互补：**定向筛选的单位成本与投毒率无关**。")
print()
print("判据：")
print("  - **低投毒率不等于低风险**：随机抽检的检出样本量按 log(1/p) 涨，p=0.1%% 要抽 %s 条。" % format(k_low, ","))
print("  - **后门要稳定植入，投毒比例通常要 0.1%~1% 量级**：太低学不到，太高反而特征明显、易被检测。")
print("  - **清洗成本是「再采一遍训练集」量级**（p=1%% 时需额外 %s 条干净数据）。" % format(int(TRAIN_N * 0.01 / 0.99), ","))
print("  - **检出手段要与攻击类型匹配**：随机抽检查标签翻转，主动筛选查后门，")
print("    而 clean-label 两者都查不出来 —— 只能靠特征层面的定向检查。")

输出：

一、随机抽检的检出概率：投毒率 p、抽检 k 条 -> 检出 = 1 - (1-p)^k
投毒率 p                 检出 95% 需抽           抽检成本                 占训练集
0.1%                      2,995         $59.90              0.2995%
0.5%                        598         $11.96              0.0598%
1.0%                        299          $5.98              0.0299%
5.0%                         59          $1.18              0.0059%
10.0%                        29          $0.58              0.0029%

   => 检出所需样本量按 log(1/p) 增长：p=0.1% 要抽 2,995 条，p=10% 只要 29 条（差 103 倍）。

二、后门的稳定性：投毒比例与触发器被学到的概率
   投毒率 0.01% -> 几乎学不到（触发器被当噪声）
   投毒率 0.10% -> 弱后门（可能不稳）
   投毒率 1.00% -> 可稳定植入
   投毒率 10.00% -> 过强，特征明显反而易被检测

三、清洗的成本：稀释投毒需要多少干净数据
   投毒率 0.1% -> 稀释到同量级需额外 1,001 条干净数据（训练集的 0.1%）
   投毒率 1.0% -> 稀释到同量级需额外 10,101 条干净数据（训练集的 1.0%）
   投毒率 10.0% -> 稀释到同量级需额外 111,111 条干净数据（训练集的 11.1%）

四、clean-label 攻击只能靠定向检查
   不改标签、只改特征 -> 标签异常检测与随机抽检都无效；
   只能针对触发器做模式匹配（例如找右下角特定色块的样本）->
   这与「低投毒率下随机抽检不经济」正好互补：**定向筛选的单位成本与投毒率无关**。

判据：
  - **低投毒率不等于低风险**：随机抽检的检出样本量按 log(1/p) 涨，p=0.1% 要抽 2,995 条。
  - **后门要稳定植入，投毒比例通常要 0.1%~1% 量级**：太低学不到，太高反而特征明显、易被检测。
  - **清洗成本是「再采一遍训练集」量级**（p=1% 时需额外 10,101 条干净数据）。
  - **检出手段要与攻击类型匹配**：随机抽检查标签翻转，主动筛选查后门，
    而 clean-label 两者都查不出来 —— 只能靠特征层面的定向检查。

三处结论：

第一，随机抽检的检出样本量按 log(1/p) 涨，所以投毒率越低越难检出。 检出概率 = 1 − (1−p)^k，要 95% 检出：p=0.1% 要抽 2,995 条（抽检成本 $59.90），p=1% 要 299 条，p=10% 只要 29 条——差 103 倍。判据：「投毒率低 = 风险低」不成立：低投毒率反而更难查出，而且它同时是最难被察觉的区间。

第二，后门要稳定植入，投毒比例通常要 0.1%~1% 量级——两头都不好。 低于 0.1% 模型把触发器当噪声、后门不稳；高于 10% 特征过于明显、反而容易被检测。所以攻击者与防御者都卡在这个窗口里，这也是为什么后门攻击的默认配置都在 0.1%~1%。

第三，清洗的成本是「再采一遍训练集」量级。 稀释到同量级需要的额外干净数据：p=0.1% → 1,001 条（训练集的 0.1%）；p=1% → 10,101 条；p=10% → 111,111 条（11.1%）。而 clean-label 攻击连随机抽检都查不出来（标签是对的、只有特征被构造），只能靠针对触发器的定向模式匹配——这恰好与「低投毒率下随机抽检不经济」互补：定向筛选的单位成本与投毒率无关。

判据：检出手段要与攻击类型匹配——随机抽检查标签翻转，主动筛选查后门，clean-label 两者都查不出来。

五、把三个模型套回本章（判据清单）

  1. ε 是成本旋钮：σ 1→10 隐私强 10 倍、训练量差 100 倍；ε=0.1 需 14.5 倍训练量 → 工业界用 ε≈3。
  2. 步数消耗隐私预算：同样 σ，训练量 ×10 → ε ×3.2 → DP 训练要早停。
  3. 裁剪范数 C 要在「分析有效」与「信号强度」之间取：C=0.25G 裁掉 75% 梯度，C≥G 则隐私分析前提失效。
  4. δ 跟着 N 走（通常 1/N 量级）。
  5. 护栏的漏过与误伤都是乘积：三层 95%/1% → 漏过 0.0125%、误伤 2.97%（29,700 个/天、186 FTE）；三层 99%/0.1% → 漏过 0.0001%、误伤 0.30%。
  6. 两类注入配不同阈值：间接注入漏过代价远高于误伤代价，直接注入反之。
  7. 护栏要进延迟与账单预算：两次额外模型调用 = 每天 $2,000（80 ms 级）到 $8,000（300 ms 级）。
  8. 投毒检出样本量按 log(1/p) 涨：p=0.1% 抽 2,995 条、p=10% 抽 29 条（差 103 倍）。
  9. 后门的有效投毒率窗口是 0.1%~1%：太低学不到，太高易被察觉。
  10. 清洗成本 ≈ 再采一遍训练集（p=1% 需额外 10,101 条干净数据）；clean-label 只能靠定向检查。

七、这三个模型判不了什么

  • ε 的绝对值依赖 q、T、δ 三者，而高斯 DP 的上界估计偏保守（真实 accountant 会紧一些）；本文只用它看「相对量级与形状」，不要当 ε 的精确预测。同理「等效训练量 ∝ σ²」是经验规律，实际还取决于任务、模型规模与优化器。
  • 护栏的拦截率/误报率是假设值。真实分类器对分布外攻击（没见过的新注入手法）的拦截率会显著低于对已知模式的拦截率——而攻击者正是要绕过已知模式。所以「95% 拦截」这个数字在对抗环境下会打折。
  • 没算对抗下的动态博弈：攻击者会针对你的护栏做优化（提示注入的迭代就是如此），于是「拦截率」不是常数而是随攻击者投入上升而下降的函数。本文的静态乘积模型给的是下限。
  • 没算数据投毒中「清洗集本身也被投毒」的情形，以及用「已训练模型的异常激活」做检测的可行性（这需要 canary 数据，而 canary 本身就是投毒目标）。
  • 三个模型都没碰偏见检测与版权归属（笔记 Q5/Q14）、以及合规侧的工时账（EU AI Act / NIST AI RMF 的文档与审计要求）——那是人力与法务成本而不是算力成本，需要另一套账。

FAQ（八、常见问题）

ε 该设多少？ 这是成本决策不是隐私决策：本模型下 σ=1 与 σ=10 之间隐私强 10 倍、等效训练量差 100 倍；要到 ε=0.1 需要 σ=3.81、训练量 14.5 倍，而工业界常用 ε=3（对应 σ=0.13，几乎不涨训练量）。另外步数也在消耗预算——同样 σ，训练量 ×10 会让 ε ×3.2，所以 DP 训练要早停。

护栏加几层好？ 加层的收益是指数的、误伤也是指数的：三层各 95%/1% → 漏过 0.0125%、但误伤 2.97%（每天 29,700 个正常请求被拦，186 FTE 复核、$5.9 万/天）；三层各 99%/0.1% → 漏过 0.0001%、误伤 0.30%。层的数量是预算问题。

直接注入和间接注入该用同一套阈值吗？ 不该。漏过 1 个间接注入（藏在 RAG/工具返回里，用户看不见）可能是一次数据外泄；误伤 1 个正常请求只是一次重试。间接注入该偏高拦截、容忍误伤；直接注入误报成本低、可以拦更狠。

护栏本身要花多少钱？ 每次请求两次额外模型调用：分类器 80 ms/$0.001 → $2,000/天（百万请求）；300 ms/$0.004 → $8,000/天。护栏要进延迟预算和账单，不只是安全预算。

怎么发现训练数据被投毒？ 看攻击类型：标签翻转可随机抽检（但检出 95% 所需抽样按 log(1/p) 涨，p=0.1% 要抽 2,995 条）；后门要对触发器做定向模式匹配（单位成本与投毒率无关）；clean-label 两者都查不出来，只能靠特征层面的定向检查。

投毒率多少最危险？ 0.1%~1% 这个窗口：低于 0.1% 模型把触发器当噪声（后门不稳），高于 10% 特征过于明显反而容易被发现。攻击者与防御者都卡在这个区间里。

数据被投毒了怎么办？ 稀释到同量级需要额外干净数据，成本量级是「再采一遍训练集」：p=1% 时需 10,101 条（训练集的 1%），p=10% 时需 111,111 条（11.1%）。
