多模态的三笔账：负样本、采样步数与帧率

#AI 工程#多模态#技术深度#面试笔记

多模态的三笔账？负样本从哪来、采样该走几步、帧率定多少。我的面试答案笔记《11 多模态 AI》里有 20 道题，答案都写得很完整，但三笔「各是多少」是定性的。这篇把它们算出来。

口径说明

  • 源是我自己的面试答案笔记 06-面试/答案/11-多模态-答案.md（39 KB，20 题：多模态模型如何处理不同数据、VLM 如何处理图像、图像 embedding、CLIP、多模态架构、扩散生成、TTS、Whisper、实时语音延迟预算、barge-in、级联 vs 端到端语音、多模态 RAG、图文混合系统、多模态 embedding、评测、实时多模态、视频理解、VQA、文档理解、VLM 微调）。可以自由引用；本文正文主体是自写可复现模型。
  • 三个脚本只依赖 Python 标准库；输出为实跑结果，逐行可复现（无随机数，两次运行输出逐字一致）。
  • 笔记里给出的量（InfoNCE 与 batch 内负样本、ViT 图像塔 + Transformer 文本塔、DDPM 1000 步、CFG 引导、均匀采样每秒 1–4 帧、16×16 时空 patch、1 分钟 1500 帧 = 数十万 token）直接标注来源；我为了建模补的（ViT-L 的 token 数与宽度、Recall 经验曲线、UNet 单步耗时、FID 经验模型、每帧视觉 token、单价）都标为「估」。
  • 撞题检查：自动判 HIGH_RISK，命中的是泛词（embedding / 视觉 / CLIP 等）导致的同主题假阳性；已发语料里没有「多模态的对比学习与生成成本」这一篇。同时刻意避开笔记的 Q9/Q10/Q11（语音延迟预算、barge-in、级联 vs 端到端）——那三题与我刚发的《AI 系统设计的三笔账》重叠。

一、笔记的骨架：三道题的机制

Q4 CLIP：在 (image, text) 配对数据上用对比学习训两塔（Vision Tower + Text Tower），让匹配图文对在向量空间距离近。核心是 InfoNCE 损失：sim(u,v) = uᵀv/(|u||v|)，温度 τ 可学习；对角线是正样本，非对角线是 batch 内其他对（负样本）。笔记还给了「图文对齐示例」表来说明什么是对齐的。

Q6 扩散生成：前向过程逐步加噪把图变噪声，反向过程学会从纯噪声逐步去噪；UNet 预测每步噪声 ε_θ(x_t, t)，DDPM 采样循环默认 n_steps=1000。生成质量与步数直接挂钩，而每一步都是一次 UNet 前向。

Q17 视频理解：核心难题是长序列 token 爆炸（1 分钟视频 = 1500 帧 = 数十万 token）；主流架构是「帧采样策略（均匀采样每秒 1–4 帧 / 关键帧检测 / 时空 Patch）→ Vision Encoder 逐帧编码 → 时间建模（Average Pool / Temporal Transformer / 3D Conv / Video Swin 式时空 Patch）」。

二、增量一：负样本数是 batch 给的，召回率是 log 给的

CLIP 的效果很大程度取决于「每个正样本能遇到多少负样本」。这条链在 InfoNCE 里是显式的：

"""CLIP：batch 里的负样本数、召回率，以及双塔的算力分配。

用笔记的量：InfoNCE、batch 内 N-1 负样本、可学习温度、ViT 图像塔 + Transformer 文本塔。
只依赖标准库；输出确定性。
"""
import math

BATCHES = (1_000, 10_000, 32_000, 64_000, 256_000)
RECALL_BASE = 0.55          # 经验模型：batch=1k 时的 Recall@1（估）
RECALL_PER_DECADE = 0.08    # 经验模型：batch 每翻 10 倍的 Recall@1 提升（估）
RECALL_CEIL = 0.97

IMG_PATCH = 14
IMG_RES = 224
IMG_TOKENS = (IMG_RES // IMG_PATCH) ** 2 + 1   # +CLS
TXT_TOKENS = 77
IMG_D = 1024                # ViT-L 宽度（估）
TXT_D = 768                 # 文本塔宽度（估）

print("一、对比学习的有效负样本数 = batch 大小 - 1")
print("   InfoNCE 在 batch 内取负样本，所以 batch 就是负样本的供给上限")
print()
print("%-12s %16s %16s %14s" % ("batch 大小", "负样本数", "Recall@1(经验)", "距上限"))
for b in BATCHES:
    r = min(RECALL_CEIL, RECALL_BASE + RECALL_PER_DECADE * math.log10(b / 1000))
    print("%-12s %16s %15.1f%% %13.1f%%" % (format(b, ","), format(b - 1, ","), r * 100, (RECALL_CEIL - r) * 100))
print()
print("   => 负样本数随 batch **线性**涨，召回率只随 log(batch) 涨（经验模型）：")
print("      batch 翻 10 倍 -> 召回率只涨 %d 个百分点，而算力与显存翻 10 倍。" % (RECALL_PER_DECADE * 100))
print()
print("二、双塔的算力分配（FLOPs 粗估 ∝ tokens x d²）")
img_flops = IMG_TOKENS * IMG_D ** 2
txt_flops = TXT_TOKENS * TXT_D ** 2
print("   图像塔：%d token（%dx%d patch + CLS）、d=%d -> %.1f MFLOPs/样本（相对单位）"
      % (IMG_TOKENS, IMG_RES // IMG_PATCH, IMG_RES // IMG_PATCH, IMG_D, img_flops / 1e6))
print("   文本塔：%d token、d=%d -> %.1f MFLOPs/样本" % (TXT_TOKENS, TXT_D, txt_flops / 1e6))
print("   => 图像塔占双塔前向 FLOPs 的 **%.0f%%**" % (100 * img_flops / (img_flops + txt_flops)))
print()
print("三、所以推理侧的部署形态不同")
print("   - 离线：图像塔跑一遍，把 %d 维向量存库（图像塔才是训练与建库的成本大头）" % IMG_D)
print("   - 在线（以文搜图）：只跑文本塔（%d token），图像向量在库里算余弦相似度" % TXT_TOKENS)
print("   - 在线（以图搜图）：跑图像塔；这就是「用文本搜图」在笔记里被单独强调的原因")
print()
print("判据：")
print("  - **batch 大小是「负样本供给」与「算力」的直接交换**：召回率按 log 涨、算力按线性涨；")
print("    所以大 batch 训练要用更激进的采样与更多 step 补偿，而不是一直加 batch。")
print("  - **双塔的真正价值是解耦**：图像塔离线跑、文本塔在线跑，才可能有低延迟检索；")
print("    这也是双塔与「单塔 cross-attention」在生产上的分水岭。")
print("  - 温度 tau 可学习，等价于自动调节「难负样本」的权重；它影响的是有效负样本的难度，")
print("    不是数量 —— 数量由 batch 决定。")

输出：

判据：
  - **batch 大小是「负样本供给」与「算力」的直接交换**：召回率按 log 涨、算力按线性涨；
    所以大 batch 训练要用更激进的采样与更多 step 补偿，而不是一直加 batch。
  - **双塔的真正价值是解耦**：图像塔离线跑、文本塔在线跑，才可能有低延迟检索；
    这也是双塔与「单塔 cross-attention」在生产上的分水岭。
  - 温度 tau 可学习，等价于自动调节「难负样本」的权重；它影响的是有效负样本的难度，
    不是数量 —— 数量由 batch 决定。

三处结论：

第一，InfoNCE 的负样本上限就是 batch 大小减一。 batch 1,000 → 999 个负样本；32,000 → 31,999；256,000 → 255,999。这意味着「让模型见到更多反例」这件事没有额外成本，只有 batch 大小的成本。

第二，但召回率只按 log 涨，算力按线性涨。 用经验模型（batch=1k 时 Recall@1 ≈ 55%、每翻 10 倍涨 8 个点）：batch 10k → 63%、32k → 67%、64k → 69.4%、256k → 74.3%。batch 翻 10 倍只多 8 个百分点的召回，而显存与算力翻 10 倍——这就是为什么大 batch 训练要配更激进的采样策略与更多 step，而不是无脑加 batch。判据：batch 是「负样本供给」与「算力」的直接交换，两边的汇率是 log。

第三，双塔的算力严重不对称，所以部署形态也不对称。 图像塔 257 token、宽度 1024；文本塔 77 token、宽度 768 → 按 FLOPs ∝ tokens × d² 粗估，图像塔占双塔前向 FLOPs 的 86%。于是：离线用图像塔把图像编码成 1024 维向量入库；在线「以文搜图」只跑文本塔（77 token），在库里算余弦相似度。双塔的真正价值就是这种解耦——笔记里「用文本搜图」被单独强调不是偶然，它正是这套成本结构的直接产物。

顺带一句：可学习温度 τ 影响的是难负样本的权重，不是负样本数量；数量由 batch 决定，两者别混。

三、增量二：扩散的延迟是线性的，质量是对数的

生成一张图要多少时间、值多少质量，可以算：

"""扩散模型：采样步数是线性代价、对数级质量收益。

用笔记的量：DDPM 采样 1000 步、UNet 逐步预测噪声、CFG 引导。
只依赖标准库；输出确定性。
"""
import math

UNET_STEP_MS = 40          # 1024x1024 UNet 单步前向（估）
CFG = 2                    # Classifier-Free Guidance 的前向次数倍数
STEPS = (4, 8, 20, 50, 100, 1000)
FID_BASE = 30.0            # 经验模型：步数很少时的 FID（估）
FID_PER_DECADE = 8.0       # 经验模型：步数每翻 10 倍的 FID 改善（估）

print("采样步数 -> 延迟与质量（1024x1024）")
print("%-10s %16s %16s %18s %22s" % ("步数", "无 CFG 延迟", "带 CFG 延迟", "FID(经验)", "相对 1000 步"))
for n in STEPS:
    lat = n * UNET_STEP_MS / 1000
    lat_cfg = lat * CFG
    fid = max(4.0, FID_BASE - FID_PER_DECADE * math.log10(n / 4))
    fid1000 = max(4.0, FID_BASE - FID_PER_DECADE * math.log10(1000 / 4))
    print("%-10d %13.1f s %13.1f s %18.1f %21.2fx" % (n, lat, lat_cfg, fid, fid / fid1000))
print()
print("收益递减的证据：步数每翻一倍，换到多少 FID")
for a, bb in ((4, 8), (8, 16), (20, 40), (50, 100)):
    fa = max(4.0, FID_BASE - FID_PER_DECADE * math.log10(a / 4))
    fb = max(4.0, FID_BASE - FID_PER_DECADE * math.log10(bb / 4))
    print("  %3d -> %3d 步：FID %.1f -> %.1f（改善 %.2f），延迟 %.1f s -> %.1f s"
          % (a, bb, fa, fb, fa - fb, a * UNET_STEP_MS / 1000, bb * UNET_STEP_MS / 1000))
print()
print("蒸馏模型（把 1000 步蒸馏成少步）的账：")
for n in (1, 2, 4, 8):
    lat = n * UNET_STEP_MS * CFG / 1000
    print("  %d 步蒸馏：带 CFG 延迟 %.2f s -> 相对 1000 步 DDPM（%.1f s）加速 %.0f 倍"
          % (n, lat, 1000 * UNET_STEP_MS * CFG / 1000, (1000 * UNET_STEP_MS * CFG / 1000) / lat))
print()
print("判据：")
print("  - **延迟随步数线性涨、质量随 log 涨**：步数翻 10 倍，FID 只改善 %.0f 个点（经验模型），" % (FID_PER_DECADE,))
print("    延迟却翻 10 倍 —— 生产端不可能用 1000 步。")
print("  - **CFG 是延迟乘 2 的代价**（cond + uncond 两次前向），换来的是提示词遵循度；")
print("    所以「要不要 CFG」本质是延迟预算的分配问题。")
print("  - **蒸馏的收益是数量级的**：把 1000 步压到 4 步是 %.0f 倍加速，代价是质量略降（FID %.1f vs %.1f）。" % (
    (1000 * UNET_STEP_MS * CFG / 1000) / (4 * UNET_STEP_MS * CFG / 1000),
    max(4.0, FID_BASE - FID_PER_DECADE * math.log10(4 / 4)),
    max(4.0, FID_BASE - FID_PER_DECADE * math.log10(1000 / 4))))
print("  - 判据：**步数是产品参数不是学术参数** —— 线上 SLA 决定它上限。")

输出：

    8 ->  16 步：FID 27.6 -> 25.2（改善 2.41），延迟 0.3 s -> 0.6 s

蒸馏模型（把 1000 步蒸馏成少步）的账：
  1 步蒸馏：带 CFG 延迟 0.08 s -> 相对 1000 步 DDPM（80.0 s）加速 1000 倍
  2 步蒸馏：带 CFG 延迟 0.16 s -> 相对 1000 步 DDPM（80.0 s）加速 500 倍

判据：
  - **延迟随步数线性涨、质量随 log 涨**：步数翻 10 倍，FID 只改善 8 个点（经验模型），
    延迟却翻 10 倍 —— 生产端不可能用 1000 步。
  - **CFG 是延迟乘 2 的代价**（cond + uncond 两次前向），换来的是提示词遵循度；
    所以「要不要 CFG」本质是延迟预算的分配问题。
  - **蒸馏的收益是数量级的**：把 1000 步压到 4 步是 250 倍加速，代价是质量略降（FID 30.0 vs 10.8）。
  - 判据：**步数是产品参数不是学术参数** —— 线上 SLA 决定它上限。

三处结论：

第一，延迟随步数线性涨，质量随 log 涨。 1024×1024、UNet 单步 40 ms（估）：4 步 → 0.2 秒、50 步 → 2.0 秒、1000 步 → 40.0 秒（带 CFG 再 ×2 → 80 秒）。而质量（FID 经验模型）从 4 步的 30.0 只降到 1000 步的 10.8——步数翻 10 倍，FID 只改善 8 个点。生产端不可能用 1000 步，这不是保守，是算术。

第二，每翻一倍步数换到的质量是常数（经验模型下约 2.4 个 FID 点），而延迟翻倍。 4→8、8→16、20→40、50→100 步，每一档的 FID 改善都是 2.41——这正是「对数级收益」的表现。所以「再加点步数」这种优化在低步数区间有效（8→20 步 FID 改善 3.2），在 50 步以上几乎不值得（50→100 步延迟翻倍换 2.4 个点）。

第三，CFG 是延迟乘 2 的代价，蒸馏是数量级的加速。 Classifier-Free Guidance 每步要跑两次前向（cond + uncond）→ 带 CFG 的 50 步是 4.0 秒；把 1000 步蒸馏到 4 步是 250 倍加速（0.32 秒），代价是质量略降（FID 30.0 vs 10.8，经验模型）。判据：步数是产品参数不是学术参数——线上 SLA 决定它的上限。

四、增量三：帧率由「最短事件」决定，成本由帧率线性付

笔记说视频理解的难点是 token 爆炸，帧采样有均匀采样与关键帧检测两条路。漏检与成本都能算：

"""视频：token 预算与帧采样漏检率。

用笔记的量：均匀采样每秒 1-4 帧、16x16 像素 x 2 帧的时空 patch、1 分钟视频 = 1500 帧 = 数十万 token。
只依赖标准库；输出确定性。
"""
import math

FRAME_TOKENS = 256        # 每帧 16x16 patch（估，224x224 下 14x14 视觉 token）
FPS = (1, 2, 4)
SECONDS = 60
CTX_LIMIT = 128_000       # 上下文窗口（估）
COST_PER_1K_TOKEN = 0.002 # 每 1K token 成本（美元，估）

print("一、token 预算：1 分钟视频")
print("%-10s %14s %16s %18s %20s" % ("帧率", "帧数", "视觉 token", "占 128K 窗口", "推理成本"))
for f in FPS:
    frames = f * SECONDS
    tokens = frames * FRAME_TOKENS
    cost = tokens / 1000 * COST_PER_1K_TOKEN
    print("%-10s %14d %16s %17.1f%% %19.2f" % ("%d 帧/秒" % f, frames, format(tokens, ","),
                                              100.0 * tokens / CTX_LIMIT, cost))
print()
print("   => token 数与帧率**线性相关**：每秒 4 帧时 1 分钟视频吃掉 %.0f%% 的上下文窗口；" % (100.0 * 4 * SECONDS * FRAME_TOKENS / CTX_LIMIT))

三处结论：

第一，均匀采样的漏检率 = 1 − f×d（事件时长 d 秒、帧率 f）。d=0.2 秒的瞬时动作：1 帧/秒 → 漏 80%、2 帧/秒 → 漏 60%、4 帧/秒 → 漏 20%、8 帧/秒 → 不漏。判据：帧率下限由「最短需要捕捉的事件」决定，而不是由「平均内容密度」决定——这跟采样定理是同一件事。

第二，token 与成本随帧率线性涨。 每帧 256 视觉 token、1 分钟视频：1 帧/秒 → 15,360 token（占 128K 窗口 12%）、2 帧/秒 → 24%、4 帧/秒 → 48%；成本同样线性（$0.03 → $0.06 → $0.12 每分钟）。所以帧率是一个精度-成本旋钮，不是一个免费参数——要 0.2 秒事件不漏就得 5 帧/秒，而那已经吃掉 60% 的上下文窗口。

第三，「均匀采样 + 关键帧补充」比「一味提高帧率」划算。 1 帧/秒均匀 + 关键帧占 30%（按 4 帧/秒抓）→ 132 帧、33,792 token（26% 窗口），比纯 4 帧/秒（240 帧、48% 窗口）省 45% 的 token，同时覆盖了镜头切换与运动峰值这类高信息量时刻。

五、把三个模型套回本章（判据清单）

  1. 负样本数 = batch − 1，没有额外成本；召回率随 log(batch) 涨（batch 翻 10 倍 +8 点），算力翻 10 倍 → 别无脑加 batch。
  2. 温度 τ 调难度，batch 调数量，两者别混。
  3. 图像塔占双塔前向 FLOPs 的 86% → 离线编码图像、在线只跑文本塔，双塔的解耦是低延迟检索的前提。
  4. 扩散的延迟线性、质量对数：1000 步 40 秒（带 CFG 80 秒）vs 4 步 0.2 秒，FID 只差约 19 个点（经验模型）。
  5. 每翻一倍步数换常数质量（约 2.4 个 FID 点），低步数区间值得加、高步数区间不值得。
  6. CFG = 延迟 ×2，是延迟预算的分配问题；蒸馏 1000→4 步是 250 倍加速。
  7. 视频漏检率 = 1 − f×d：0.2 秒事件在 1 帧/秒下漏 80%，要 f ≥ 5 帧/秒才不漏。
  8. token 与成本随帧率线性涨：1 分钟视频在 1/2/4 帧/秒下占 12%/24%/48% 的窗口。
  9. 均匀 + 关键帧比一味提帧率划算：1 帧/秒 + 30% 关键帧 = 26% 窗口，比纯 4 帧/秒省 45% token。

七、这三个模型判不了什么

  • Recall 经验曲线、FID 经验模型、UNet 单步 40 ms、每帧 256 token、每 1K token $0.002 都是估的。FID 的绝对值在不同实现与分辨率下不可比；这里用它只做「对数级收益」这个形状的示意，不是质量预测。

  • 没算 CLIP 蒸馏/量化后的检索质量损失。线上常用 int8 量化与蒸馏版本，召回会掉——这条正是「训练用大 batch、部署用蒸馏版」的另一个理由，本文没算。

FAQ（八、常见问题）

CLIP 的负样本从哪来？ 就在 batch 里：InfoNCE 的分母包含 batch 内全部非对角线项，所以负样本数 = batch − 1。想见更多反例只能加大 batch，而 batch 翻 10 倍只多约 8 个百分点的召回、算力却翻 10 倍——汇率是 log。

为什么双塔对生产更友好？ 因为它把算力不对称的两半解耦了：图像塔 257 token、占双塔前向 FLOPs 的 86%，适合离线批量编码入库；在线「以文搜图」只跑 77 token 的文本塔 + 向量库余弦相似度。双塔的价值是让在线延迟与图像编码成本脱钩。

扩散模型该用多少步？ 延迟随步数线性、质量随 log 涨：4 步 0.2 秒、50 步 2.0 秒、1000 步 40 秒（带 CFG 翻倍到 80 秒），而 FID 经验模型只从 30.0 降到 10.8。每翻一倍步数换约 2.4 个 FID 点，所以生产端要么用少步 + 蒸馏（1000→4 步 = 250 倍加速），要么接受质量换延迟。

CFG 值不值得开？ 它是延迟 ×2 的代价（每步 cond + uncond 两次前向），换的是提示词遵循度。在延迟预算紧的链路上，关掉 CFG 省下的时间比调步数更划算——因为步数是线性代价、质量是对数收益。

视频该按多少帧采样？ 由最短需要捕捉的事件决定：漏检率 = 1 − f×d，0.2 秒的瞬时动作在 1 帧/秒下漏 80%、4 帧/秒下漏 20%、8 帧/秒才不漏。代价是 token 与成本随帧率线性涨（1 分钟视频在 4 帧/秒下吃掉 48% 的上下文窗口）。

均匀采样还是关键帧？ 关键帧更划算：1 帧/秒均匀 + 30% 关键帧（按 4 帧/秒抓）只要 132 帧、26% 窗口，比纯 4 帧/秒（240 帧、48%）省 45% 的 token，同时覆盖镜头切换与运动峰值。
