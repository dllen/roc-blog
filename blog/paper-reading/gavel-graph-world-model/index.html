GAVEL 详解：给 LLM 配一张会预测后果的图

#GAVEL#图世界模型#机器人规划#LLM Agent#状态追踪

一句话总结

GAVEL 就像给大语言模型（LLM）配备了一张动态的“因果地图“：每做一个动作之前，先在地图上“预演“一遍后果，发现不对就自动修复，不用每次都去问模型。这样做出来的机器人规划，成功率从 41% 暴涨到 92%，而且推理成本更低。

背景：LLM 做机器人规划的三大噩梦

想象你让一个机器人帮你收拾房间：“先把桌上的书放进书架，然后把花瓶放到窗台，最后把脏衣服扔进洗衣机。“这句话听起来简单，但对 LLM 来说，它要面对三个几乎无解的难题：

1. 物理约束违反：机器人不知道“物理定律“

LLM 没有真正的身体，它不知道：

  • 花瓶是玻璃的，不能用力捏
  • 书比书架的隔层宽，硬塞会坏
  • 机器人的手臂伸不到某个角度

结果是：LLM 生成的规划物理上不可执行，但它自己不知道。

2. 无法恢复：错了就错了

假设机器人已经把花瓶打碎了，LLM 还接着执行原计划的后续步骤。它不知道世界已经变了，还在按“花瓶还在“的前提继续调度。

就像一个没有记忆的人，每次做完动作就忘记自己做了什么，后面每一步都建立在错误的世界状态之上。

3. 物体跟丢：不知道东西在哪

在真实家庭环境中，很多东西你看不到（抽屉里、沙发底下、柜子后面）。LLM 不知道：

  • 钥匙可能在卧室，也可能在客厅
  • 我有 60% 的把握它在卧室床头柜里
  • 但我不知道钥匙到底在不在鞋盒里

LLM 经常编造物体位置（幻觉），或者忘记自己已经移动过某个东西。

核心方法：图世界模型

GAVEL 的核心思想很简单：不要让 LLM 在脑子里模拟所有事情，而是用一个外部的“图“来记录世界的状态和变化规律。

什么是一张“会预测后果的图“？

把这张图想象成一个数字化的房间地图：

┌─────────────────────────────────────────┐
│  图世界模型（Graph World Model）          │
├─────────────────────────────────────────┤
│                                         │
│  📦 物体节点                             │
│    ├── 位置: 厨房台面（60%）/ 洗碗机（40%）│
│    ├── 状态: 干净 / 脏                   │
│    └── 属性: 玻璃材质 / 陶瓷材质          │
│                                         │
│  🔗 关系边                               │
│    ├── 书 "在" → 书架第3层               │
│    ├── 花瓶 "放在" → 窗台                │
│    └── 脏衣服 "在" → 卧室地板            │
│                                         │
│  ⚙️ 动作规则                             │
│    ├── 拿起(X): 需要 X可见 且 手臂够得着  │
│    ├── 放下(X,Y): X当前在手中            │
│    └── 打开(X): X是容器 且 X是关闭的     │
│                                         │
│  📊 概率信念                             │
│    └── 对于不可见的物体，维护一个概率分布 │
│                                         │
└─────────────────────────────────────────┘

关键点：这张图是独立于 LLM 的，LLM 只负责“说我要做什么“，而这张图负责“验证这么做对不对“。

三步走：预测 → 检测 → 修复

第一步：预演（Pre-execution Prediction）

当 LLM 说：“机器人去拿花瓶，放到窗台上。”

GAVEL 不急着执行，而是先在图上模拟：

LLM 的指令：
  "拿起花瓶 → 放到窗台"

图世界模型的预演：
  Step 1: 检查"花瓶"在哪里？
    → 查图：当前位置 = 客厅茶几
    → 状态：可见 ✓

  Step 2: 检查"拿起"动作的前置条件
    → 花瓶可见 ✓
    → 机器人手臂够得着茶几高度 ✓
    → 预测结果：花瓶从茶几 → 机器人的手

  Step 3: 检查"放到窗台"的前置条件
    → 窗台高度? 1.2米
    → 机器人手臂最大伸展角度? 可达 ✓
    → 预测结果：花瓶从机器人的手 → 窗台

  Step 4: 更新图状态
    → 花瓶位置更新为"窗台"
    → 标注置信度：高（因为所有条件都满足）

全程不需要调用 LLM，图本身就能推演。

第二步：违规检测（Violation Detection）

如果预演中发现问题，图就会“报警“：

❌ 检测到违规：

LLM 说："把玻璃花瓶放进微波炉加热"

图世界模型预演：
  Step 1: 检查"玻璃"属性
    → 材质: 玻璃 ❌
    → 动作: "加热"
    → 后果预测: 花瓶会碎 / 爆炸 💥

  → 违规类型: 物理约束违反
  → 错误来源: 直接可从图的属性推导，不需要问 LLM

这就是 GAVEL 名字的精髓——Graph Action Verification before Execution and Learning。

第三步：自修复（Self-Repair）

检测到错误后，GAVEL 不是立刻让 LLM 重新规划，而是先尝试自己修：

检测到错误：花瓶（玻璃材质）不能放进微波炉

GAVEL 自修复尝试：
  方案 A: 把"加热"改成"常温放置"
    → 图验证: 可行，花瓶完好 ✓
    → 执行这个替代方案

实验效果

GAVEL 在 BEHAVIOR-1K 基准（100 个单任务 + 500 个多任务指令）上验证：

单任务（100 个长周期任务）

配置成功率
Qwen3-8B（baseline，无图）41.2%
Qwen3-8B + GAVEL91.8%
提升幅度+50.6%

多任务（500 个指令，每个含多个子任务）

配置成功率
Qwen3-8B（baseline）19.9%
Qwen3-8B + GAVEL92.6%
提升幅度+72.7%

多任务提升更显著，因为多任务更容易遇到“前面步骤影响后面步骤“的问题，而这正是图世界模型最擅长解决的场景。

其他收益

  • 移动距离减少约 5.4%：图能计算“最优任务顺序“，减少机器人来回跑的无效移动
  • LLM 调用次数大幅减少：简单错误由图自动修复，不需要重新调用 LLM

为什么“状态跟丢“是长周期 Agent 失败的根源

用一个生活场景理解：

你在厨房做饭，中途去客厅接了个电话。回来后继续做饭，但你记得炉子上还煮着东西，知道火候开到几档，清楚菜切到了哪一步。

现在把这个能力从人类拿走：

你在厨房做饭，中途去客厅接了个电话。回来后，你完全不记得炉子上有没有东西、火候是多少、菜切到哪了。你只能重新猜测现在厨房是什么状态。

这就是当前 LLM Agent 的处境：每一步之间，LLM 丢失了中间状态。

场景人类做法LLM（无图）做法
任务做到一半被打断记得做到哪了，从断点继续忘记前面做了什么，重新从零规划
某个动作改变了环境立刻感知到变化，调整后续计划不知道变化了，按原计划执行
物体被移动了知道“钥匙不在桌上，可能在抽屉“坚持认为“钥匙还在桌上“

GAVEL 的图世界模型，本质上是给 LLM 外挂了一个永远不会忘的工作记忆，每一步操作后都更新状态，每一步执行前都参考当前真实状态。

不只是机器人：通用 Agent 的状态追踪

GAVEL 的思路可以推广到所有长周期 Agent 场景：

传统软件 Agent 的问题：
  → 转账后账户A余额变化，LLM 不知道
  → 后续购买时用错误的余额做判断

GAVEL 风格的解决：
  → 用图记录每个账户的实时余额
  → 转账后自动扣减/增加对应金额
  → 购买前先查图的当前余额，不够就拒绝或提示

核心思想：无论软件 Agent 还是机器人 Agent，都需要一种独立于 LLM 的状态追踪机制，让 LLM 每次做决策时都有一个“真实世界状态“的参考，而不是靠记忆（幻觉的主要来源）。

三个真实软件 Agent 场景

场景 1：文件系统操作 Agent

用户说“把最近下载的 PDF 都移动到 Documents 文件夹，然后把里面包含’财报’关键词的文件重命名为’2024 财报-原文件名’“。

  • 纯 LLM 的问题：移动完成后，LLM 不知道哪些文件移动了；重命名时不知道文件名已经变了。
  • GAVEL 风格的解决：用图记录文件系统的当前状态，移动操作后更新节点，重命名时查询当前真实文件名。

场景 2：工单处理 Agent

用户说“先把这个工单标记为进行中，然后分配给张三，等张三回复后自动升级给李四“。

  • 纯 LLM 的问题：工单状态在 Jira/飞书等外部系统，LLM 无法感知中间变化；超时卡住时不知道卡在哪。
  • GAVEL 风格的解决：用图记录每个工单的当前状态（待处理/进行中/已分配/已超时），外部事件触发图更新，超时规则由图自动检测并触发升级。

场景 3：账户余额操作 Agent

用户说“从账户 A 转 1000 到账户 B，然后用账户 B 的钱去买东西“。

  • 纯 LLM 的问题：转账后账户余额变化，LLM 不知道；后续购买时用错误的余额做判断。
  • GAVEL 风格的解决：用图记录每个账户的实时余额，转账后自动扣减/增加金额，购买前查当前余额，不够就拒绝或提示。

总结

GAVEL 的核心贡献是引入了**图世界模型（Graph World Model）**作为 LLM 的外部验证层：

  1. 图负责“懂物理“：记录物体属性和动作规则，检测物理上不可行的动作
  2. 图负责“记状态“：每步执行后更新状态，解决“状态跟丢“问题
  3. 图负责“自动修“：简单错误图自己修，只有语义问题才问 LLM
  4. 图负责“算概率“：对不可见物体维护概率分布，支持有依据的猜测

这张“因果地图“让 LLM 从“盲目执行“变成了“有地图导航的智能执行“，是长周期 Agent 规划领域的一个实用且有效的突破。
