实验 3：蒸馏你自己的评测集与提示词搜索

#软件工程#生成式 AI#课程笔记#Agent 记忆

自己写的助手「经常会给你惊喜，但是又经常会给你惊吓」——口癖不对，同一种毛病反复纠正；更麻烦的是手工调好的提示词会随着模型或 harness 升级而失效，「一夜回到解放前」。《生成式软件工程》实验 3 把这件事做成了闭环。

它的做法是：把你的纠正历史沉淀成一个持续增长的评测集，然后在里面搜索一个提示词，让 Agent 生成的输出越来越像你的思维方式。这个实验本身是建议性质、不记分，但它是全课讲义的收口——第 13 讲讲 informal verification，第 14 讲讲「谁来判断 AI 把事情做成了」，而这里给出的是怎么让判断持续运转。

这篇做两件事：把讲义最精细的两处方法论写成能跑的检查器，并如实报告它们能做到什么、做不到什么。

一、评测集：为什么「完全对齐」不可能

反馈信号有两个来源。第一个是你自己针对某个任务完成的文稿或答案；第二个是你和 Agent 的聊天记录里那些后续纠正——把模型做错的地方列为不良反馈，它再次犯同类错误就扣分。

讲义对第一个来源给了一个很硬的限定：同一个任务在不同时刻交给同一个人，因为处境不同，人自己也会给出不同答案，所以**「完全对齐」是不可能的**；但一个人的思维方式在一段时间内相对稳定，于是「能否得到正确的观点」成为合理的评判标准。

对第二个来源，讲义给的警告更实用：有些纠正是带着额外的、没有交代清楚的上下文来的，记忆系统容易把这种有限定性的纠正夸大成通用规则，反而降低体验。这条警告在第三节会变成一个能跑的对照。

评测集本身用 Markdown 之类便于维护的格式存着，「在自己心情好的时候」持续扩展，发现旧数据有问题再改——这一条听起来随意，但恰恰是它能长期存活的原因：评测集是活的，不是配置项。

二、把「宽松篇幅下覆盖主要观点」写成可判定的规则

讲义在方法论上最精细的一句，是关于怎么设计「对齐」的评价：

我们当然可以直接让 Agent 去判定「输出是否和人类一致」（甚至更极端一些，算一个 longest common subsequence）——但这显然不是好的反馈。

理由讲义已经给了：人两次做同一件事会给出不同结果，所以字符串一致不是对齐的标准。更合理的标准是「是否在有允许一定宽松篇幅的情况下，覆盖了原先的主要观点」。

这句话本身还是定性的，但它可以被拆成三条能机械检查的规则：主要观点列成要点清单，要求全覆盖；宽松篇幅变成区间（相对参考长度的倍数）；再加一条廉价的反向检查——不允许出现与参考相反的断言。下面这段代码给出规则判定，并与 LCS 同一批评分作对照：

"""把「宽松篇幅下覆盖主要观点」写成可判定的规则，并与字符串一致/LCS 对照。

讲义说：让 Agent 直接判定「输出是否和人类一致」（甚至算 longest common subsequence）
显然不是好反馈；更合理的标准是「是否在有允许一定宽松篇幅的情况下，覆盖了原先的主要观点」。
下面把它拆成三条可机械检查的规则，跑正样本与反样本，并让 LCS 同一批评分作对照。
"""

REFERENCE_POINTS = {
    "先界定问题边界": ["界定", "边界", "范围"],
    "给出可验证的判据": ["判据", "可验证", "指标"],
    "说明取舍代价": ["代价", "取舍", "权衡"],
    "承认不确定的部分": ["不确定", "未必", "存在风险"],
}
REFERENCE = ("界定问题的边界之后，需要给出可验证的判据；"
             "每个判据都伴随取舍代价，也承认存在不确定的部分。")

LENGTH_RATIO_MAX = 2.0        # 宽松篇幅上限：不超过参考长度的 2 倍
LENGTH_RATIO_MIN = 0.4        # 下限：太短即使覆盖也不算数
COVER_RATIO_MIN = 1.0         # 主要观点必须全覆盖
CONTRADICTIONS = {"承认不确定的部分": ["保证不出错", "必然正确", "完全不会"]}


def check(candidate):
    """返回 (违反明细, 要点覆盖率, 篇幅倍数)。"""
    violations = []
    missing = [p for p, keys in REFERENCE_POINTS.items() if not any(k in candidate for k in keys)]
    if missing:
        violations.append("要点未覆盖: %s" % "、".join(missing))
    ratio = len(candidate) / len(REFERENCE)
    if ratio > LENGTH_RATIO_MAX:
        violations.append("篇幅超宽松上限(%.2fx)" % ratio)
    if ratio < LENGTH_RATIO_MIN:
        violations.append("篇幅低于下限(%.2fx)" % ratio)
    for point, banned in CONTRADICTIONS.items():
        for b in banned:
            if b in candidate:
                violations.append("与参考相反的断言: %s" % b)
    return violations, (len(REFERENCE_POINTS) - len(missing)) / len(REFERENCE_POINTS), ratio


def lcs_ratio(x, y):
    """最长公共子序列长度 / 参考长度 —— 讲义批评的「字符串一致」口径。"""
    m, n = len(x), len(y)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            dp[i][j] = dp[i - 1][j - 1] + 1 if x[i - 1] == y[j - 1] else max(dp[i - 1][j], dp[i][j - 1])
    return dp[m][n] / len(x)


SAMPLES = {
    "好答案（同义改写）":
        "先把问题的范围界定清楚，再给出一条可验证的判据；每条判据背后都有取舍的代价，也存在风险，结论未必成立。",
    "漏要点":
        "先把问题的范围界定清楚，然后给出一条可验证的判据。",
    "超长":
        "界定问题的边界之后，需要给出可验证的判据；每个判据都伴随取舍代价，也承认存在不确定的部分。"
        "补充说明一：这里再展开讲一讲为什么边界重要，因为边界决定了后续所有取舍的代价，代价又决定了哪些不确定可以承担。"
        "补充说明二：还要强调判据必须可验证，否则讨论会滑向各说各话，每个判据背后都有代价，代价又带来新的不确定。",
    "含矛盾":
        "界定问题的边界之后，需要给出可验证的判据；每个判据都伴随取舍代价，而且保证不出错。",
    "逐字抄前半段":
        "界定问题的边界之后，需要给出可验证的判据；",
}

print("%-18s %-8s %-8s %-10s %-8s %-8s" % ("样本", "要点覆盖", "篇幅倍数", "违反条数", "LCS", "判定"))
for name, cand in SAMPLES.items():
    v, cover, ratio = check(cand)
    lcs = lcs_ratio(cand, REFERENCE)
    print("%-18s %-8s %-8.2f %-10d %-8.3f %-8s"
          % (name, "%.2f" % cover, ratio, len(v), lcs, "通过" if not v else "不通过"))
    for item in v:
        print("      - %s" % item)

print()
print("判据对照：")
lcs_of = {name: lcs_ratio(text, REFERENCE) for name, text in SAMPLES.items()}
ok = [name for name, text in SAMPLES.items() if not check(text)[0]]
print("  LCS 最高的样本 =", max(lcs_of, key=lambda k: lcs_of[k]), "(%.3f)" % max(lcs_of.values()))
print("  通过规则检查的样本 =", "、".join(ok) if ok else "无")
print("  LCS 最低的样本 =", min(lcs_of, key=lambda k: lcs_of[k]), "(%.3f)" % min(lcs_of.values()))
print("  -> LCS 把「逐字抄前半段」排第一(1.000)，规则判它不通过；"
      "规则唯一放行的是「同义改写」(LCS 0.529)，而 LCS 会把它排在「漏要点」(0.560)之后")
样本                 要点覆盖     篇幅倍数     违反条数       LCS      判定      
好答案（同义改写）          1.00     1.13     0          0.529    通过      
漏要点                0.50     0.56     1          0.560    不通过     
      - 要点未覆盖: 说明取舍代价、承认不确定的部分
超长                 1.00     3.38     1          0.296    不通过     
      - 篇幅超宽松上限(3.38x)
含矛盾                0.75     0.91     2          0.854    不通过     
      - 要点未覆盖: 承认不确定的部分
      - 与参考相反的断言: 保证不出错
逐字抄前半段             0.50     0.47     1          1.000    不通过     
      - 要点未覆盖: 说明取舍代价、承认不确定的部分

判据对照：
  LCS 最高的样本 = 逐字抄前半段 (1.000)
  通过规则检查的样本 = 好答案（同义改写）
  LCS 最低的样本 = 超长 (0.296)
  -> LCS 把「逐字抄前半段」排第一(1.000)，规则判它不通过；规则唯一放行的是「同义改写」(LCS 0.529)，而 LCS 会把它排在「漏要点」(0.560)之后

对照结果是讲义那句话的数值版本：**LCS 最高分（1.000）落在「逐字抄参考前半段」这个样本上，规则判它不通过（漏两个要点）；规则唯一放行的「同义改写」，LCS 只有 0.529，被排在「漏要点」（0.560）后面。**两种口径排出的名次几乎相反——这不是调参问题，是评价目标不同：LCS 问「像不像这句话」，规则问「该说的说了没有」。

另外两处细节也值得看：「超长」样本要点全覆盖、却因为篇幅 3.38 倍被判不通过（宽松不等于没有边界）；「含矛盾」样本因为一句「保证不出错」多了一条违反——这条检查很便宜，但它抓的正是人类读者最容易滑过去的那类错误。

评价还可以拆维度：行文、断句、措辞、对读者知识的假设。讲义对此的判断是「在有明确维度时，Agent 就会针对维度设计出分别改进的提示词」——这句话的工程含义是：评价维度不是写给人看的备注，而是提示词搜索的目标函数维度。四个维度各配一组规则，搜索就从「找一个更好的提示词」变成「每个维度各改进一处」，冲突也显式化了（某次改动让措辞变好、却让断句变差，此时要看见这个取舍，而不是让一个总分把它藏起来）。

三、隔离重做循环：搜索提示词，以及它怎么把提示词写脏

讲义给出的基本流程有三步：要求 Agent 在看不到你的输出的隔离上下文里完成任务；比对 Agent 输出与你的输出的主要不同；改提示词重跑，看是否改进，重复到对齐。

讲义随后列了四种失败模式，值得整段抄下来：看到表象而看不到本质；AI 自己提炼的改进方案不起效果；提示词污染上下文导致 overfitting；以及「骂过」之后的过度反应——把某些词语或工作方式一刀切列为禁止，伤害到确实需要它们的上下文。

这些失败模式有一个共同的结构：它们都是评分口径与搜索目标错配的产物。下面这个玩具模型把这件事跑出来。它不是对真实模型的预测，而是一个评分口径的玩具：Agent 覆盖「提示词点名的要点 + 任务基础覆盖的要点」，多覆盖本题不要求的要点要扣分（对应污染与误伤）。

"""隔离重做循环的玩具模型：提示词搜索怎么在单题上过拟合、在评测集上退化。

这不是对真实 LLM 的预测，而是一个评分口径的玩具模型：
Agent 覆盖「提示词里点名的要点 + 任务基础覆盖的要点」；多覆盖本题不要求的要点要扣分
（对应讲义说的「提示词污染 / 过度反应误伤上下文」）。
"""
TASKS = {
    "任务1": {"points": ["a", "b", "c"], "base": ["a"]},
    "任务2": {"points": ["a", "b", "d"], "base": ["a"]},
    "任务3": {"points": ["e", "f", "g"], "base": ["a"]},
}
EVAL_SET = ["任务1", "任务2"]
HOLDOUT = ["任务3"]
UNIVERSE = ["a", "b", "c", "d", "e", "f", "g"]


def score(task_name, prompt_rules):
    """覆盖本题要点的比例，减去「提了本题不要求的要点」的误伤扣分。"""
    t = TASKS[task_name]
    covered = set(t["base"]) | (set(prompt_rules) & set(t["points"]))
    hit = len(covered & set(t["points"]))
    miss = len(set(t["points"]) - covered)
    stray = len(set(prompt_rules) - set(t["points"]))
    return (hit - 0.5 * stray - miss) / len(t["points"])


def evaluate(rules, tasks):
    return sum(score(t, rules) for t in tasks) / len(tasks)


def greedy(target_task, pool, tasks=None, rounds=3):
    """贪心搜索：每轮挑一个让目标分数最高的规则加入。

    target_task 不为空 -> 只盯这一题；否则按 tasks 上的均分来挑。
    """
    rules, trace = [], []
    for _ in range(rounds):
        best, best_s = None, None
        for cand in pool:
            trial = rules + [cand]
            s = score(target_task, trial) if target_task else evaluate(trial, tasks)
            if best_s is None or s > best_s:
                best, best_s = cand, s
        rules.append(best)
        trace.append(list(rules))
    return rules, trace


pool = UNIVERSE
print("== 只盯着任务1 贪心优化 ==")
rules, trace = greedy("任务1", pool)
for i, r in enumerate(trace, 1):
    print("  第%d轮 加入 %s -> 单题分 %.3f | 评测集均分 %.3f | 留出集均分 %.3f"
          % (i, r[-1], score("任务1", r), evaluate(r, EVAL_SET), evaluate(r, HOLDOUT)))
print("  最终提示词规则 =", rules)

print()
print("== 盯着整个评测集贪心优化 ==")
rules2, trace2 = greedy(None, pool, tasks=EVAL_SET)
for i, r in enumerate(trace2, 1):
    print("  第%d轮 加入 %s -> 评测集均分 %.3f | 留出集均分 %.3f | 任务1 %.3f"
          % (i, r[-1], evaluate(r, EVAL_SET), evaluate(r, HOLDOUT), score("任务1", r)))

print()
print("== 限定性纠正被写成全局规则 ==")
scoped_to = "任务3"          # 这次纠正只在那次任务的上下文里成立
local_rule = ["e", "f"]      # 记忆系统把它记成了通用规则
for t in ["任务1", "任务2", "任务3"]:
    as_global = score(t, local_rule)
    as_scoped = score(t, local_rule) if t == scoped_to else score(t, [])
    tag = "(纠正在此生效)" if t == scoped_to else "(与这次纠正无关)"
    print("  %s %s: 记成全局规则 %.3f | 只在该任务生效 %.3f" % (t, tag, as_global, as_scoped))
== 只盯着任务1 贪心优化 ==
  第1轮 加入 b -> 单题分 0.333 | 评测集均分 0.333 | 留出集均分 -1.167
  第2轮 加入 c -> 单题分 1.000 | 评测集均分 0.583 | 留出集均分 -1.333
  第3轮 加入 a -> 单题分 1.000 | 评测集均分 0.583 | 留出集均分 -1.500
  最终提示词规则 = ['b', 'c', 'a']

== 盯着整个评测集贪心优化 ==
  第1轮 加入 b -> 评测集均分 0.333 | 留出集均分 -1.167 | 任务1 0.333
  第2轮 加入 c -> 评测集均分 0.583 | 留出集均分 -1.333 | 任务1 1.000
  第3轮 加入 d -> 评测集均分 0.833 | 留出集均分 -1.500 | 任务1 0.833

== 限定性纠正被写成全局规则 ==
  任务1 (与这次纠正无关): 记成全局规则 -0.667 | 只在该任务生效 -0.333
  任务2 (与这次纠正无关): 记成全局规则 -0.667 | 只在该任务生效 -0.333
  任务3 (纠正在此生效): 记成全局规则 0.333 | 只在该任务生效 0.333

三段结果对应三个不同的问题。

第一段是只盯着单题优化的情形：单题分一路升到 1.000，评测集均分只到 0.583，而留出集从 -1.167 掉到 -1.500。单题满分和整体变好是两件事，差别全在「提示词里被点名的要点有没有污染其他任务」。

第二段是改成盯着整个评测集的情形：评测集均分从 0.333 涨到 0.833，留出集却从 -1.167 一路跌到 -1.500。评测集涨、留出集跌，这是 overfitting 的教科书形态——评测集里有什么，决定了提示词会被写成什么样。这也解释了讲义为什么强调评测集要持续增长：它既是尺子，也是模具。

第三段是作用域。某次纠正只在任务 3 的上下文里成立（那次任务确实需要那两个要点），记忆系统却把它记成了通用规则：与这次纠正无关的任务 1、任务 2 从 -0.333 掉到 -0.667，而任务 3 两种写法完全一样（0.333）。作用域缺失换来的收益是零，代价是误伤——所以正确的做法不是「不要写规则」，而是把规则和它的适用范围一起记下来。

四、让 Deep Research Agent 参与：在设计空间里跳跃

讲义给打破僵局的办法是引入 Lab2 的 Deep Research Agent：通过互联网搜索与持续的多样性采样，模型可能打破固有思维，取得更好的效果。

这与第 10 讲的理论判断是同一件事：在同一个设计空间里累加约束学不会「好」，所以需要设计空间的跳跃，而不是让模型在原地打转。用实验 3 的语言说——提示词搜索只在「措辞层」打转时，你得先允许它去换一种解法，否则第三次迭代加上去的每一条规则都只是污染。

讲义还有一句诚实的提示：不幸的是在这个实验里用更强的基础模型效果显著更好，但无论用什么模型都能取得正向效果。这句话该被当成结论的一部分，而不是抱怨——它意味着闭环的价值不依赖模型上限，而依赖你有没有把反馈记下来。

五、这套东西的边界

自检工具不是评分标准，这个实验的检查器同样有明确边界：

  • 要点清单是人写的，规则只验证覆盖，不验证正确。 规则能说「这句漏了『说明取舍代价』」，但说不出「这句的取舍代价说得对不对」。后者仍然要靠人，或者靠一个更强的模型。
  • 关键词匹配当不了语义判定。 「承认不确定」和「未必成立」被当作同一个要点，是为了让规则可执行；真实的同义改写远多于此。
  • 玩具模型不预测真实模型的行为。 它只证明一件事：换成单题最优、换成带作用域的规则，结论就会变。真实模型会不会这样，取决于采样、上下文与工具。
  • 对齐的终点是你的过去。 讲义的循环以「你的历史输出」为 oracle，持续优化的方向是「越来越像你」。但 Lab2 的价值恰恰在于 Agent 能带来你不知道的资料——对齐做得太彻底，Agent 可能变成一面回音壁：越来越擅长复述你的思维方式，越来越不擅长挑战它。一个务实的折中是双评测集：一个「像我」的集合保证日常输出可用，一个「超过我」的集合（来自深度研究的发现、来自你事后承认「它比我当时的答案好」的案例）保留被惊喜的能力。讲义结尾说「我也很希望这个对齐的过程能成为基础模型能力的一部分」——当对齐成为基础设施，区分「对齐你的偏好」与「复制你的局限」就成了用户自己的责任。

FAQ（六、常见问题）

Q：为什么不干脆让模型自己判断「输出像不像我」？

A：讲义明确说这不是好反馈，理由是同一个人在不同时间做同一任务会给出不同答案——那样一来，任何稳定的标准答案都是假的。而且模型自评还多一层问题：它会倾向于奖励自己熟悉的表达方式。实验室里可核的替代方案是把「像你」拆成要点清单 + 篇幅区间 + 矛盾检查，至少让判定可复算、可争论。

Q：评测集要多大才有用？

A：讲义没给数字，它给的是机制：评测集要持续增长、格式便于维护、发现旧数据有问题可以改。判断标准也不该是数量，而是「它能不能区分出明显更好的答案」。如果一轮迭代后所有样本得分都一样，说明这把尺子量不出差异，该换维度而不是加样本。

Q：这套东西会不会变成「不断给自己加规则」的负担？

A：讲义把「过度反应」列为失败模式之一，机制上就是这条负担的来源。可行的做法是给规则分级：通用的放全局提示词、限定的放任务局部提示词，并且每条规则都记录它是在什么上下文里被学到的。没有作用域的记忆，积累得越多，误伤越多。

Q：这是不是又一个「让 AI 自己给自己打分」的循环？

A：差别在 oracle 的来源。模型自评是循环论证；实验 3 的 oracle 是你自己过去的输出与纠正——它不来自模型，所以模型没法通过换一种说法来骗过去。它仍然会漂（人会漂，你的参考答案也会过时），但漂的方向是可观察的，这正是评测集需要持续维护的原因。
