周报：Agent 架构、评测与验证的一次集中观察

#周报#weekly

本期周报覆盖 10 月 7 日到 11 月 9 日的收件箱、归档文章与剪藏，共 217 条原始条目，以下按主题归类摘录其中有独立信息量的部分。每条给出链接、一段摘要和一句点评；只做导读，不搬运原文。

一、Agent 架构：从脚手架走向状态机

这一期数量最多的主题。素材共同指向一个方向：给 Agent 搭脚手架（harness）的做法正在让位于给 Agent 设计状态与验证机制。

  • Super-agent 设计探索：迈向更自主的 Agent 系统 —— DeepSeek Harness 团队对更自主 Agent 系统的架构思路探讨。点评：文章自己声明这是架构思路而非产品功能介绍，这类自我限定反而值得信任。
  • 评 DeepSeek Super-Agent 探索：为什么小秘书遇上大工程就拉胯？ —— 作者的判断是超级助理缺的不是更多 Session，而是别的什么东西。点评：这类批评比原方案自述更有信息量，因为它指出了缺口而非复述优点。
  • 从长程 Agent 到 Super-agent，解锁更多场景 —— 阿里云 AgentCore 视角的演进梳理：对话到动手，简单任务到长程任务，再到跨实体任务。点评：三段式划分给「长程」这个词提供了可操作的定义。
  • Agent State Machines: Building Deterministic Scaffolding for Agents —— Josh Rosen 提出用显式状态机为 Agent 提供确定性脚手架。点评：「确定性」是对当前脚手架范式最直接的反驳——预测式接口的每一步都在赌。
  • Loops and Graphs: how to stop babysitting agents and only approve the last step —— 用循环与图取代人工盯梢，只在最后一步审批。点评：把审批点从每轮移到终点，是把「信任」问题换成「可回滚」问题的思路。
  • Graph Engineering: how to build the agent system that replaced loops —— 同一位作者的进一步主张。点评：与前一条正好构成一组对照，可看成一个命题的正反面。
  • 从长程 Agent 到 Super-agent，解锁更多场景 与 小秘书遇上大工程 两篇的共同结论：会话数量不是扩展性的解法，任务分解与状态管理才是。
  • 深度解析 Codex Harness 架构及其全新上下文压缩记忆体系的设计思路 —— 基于 Codex CLI 开源源码剖析 Harness 与记忆机制。点评：源码可查的技术梳理比产品宣传页可靠得多。
  • Agent 的工具箱，正在收缩成一个 exec 一类的观点在同期反复出现：不再逐个给模型点工具，而是给一个受控沙箱让它写代码调用工具。点评：Code Mode 减少了工具描述的 token 成本，但也把「选错工具」换成了「写错代码」。
  • ThinkRail：JetBrains 开源的智能体 IDE —— 围绕 pi 编码智能体，用 git-worktree 隔离并行任务的工作区。点评：worktree 隔离 + 规范文档图谱，是本篇主线在工作区侧的具体化。
  • Personal Agent 落地思考：主动性从哪来，又卡在哪？ —— Qoder 团队关于 Agent 主动性的思考。点评：主动性的难点在于授权边界，而非能力边界。
  • 交付周期从 51 天缩短到 14 天，多 Agent 协作产品自进化背后的组织重构 —— Agentic SOC 产品的组织改造记录。点评：交付周期缩短四分之三的同时，团队结构也变了——这部分往往被一句「效率提升」盖过。

二、评测与验证：这期最一致的主题

多个来源不约而同地指向同一个位置：模型能力不是瓶颈，判断产出对不对才是。

  • Automating eval design and hillclimbing with Claude —— Anthropic 讲评测设计与自动爬坡的基本原则。点评：标题里的 without fooling yourself 是重点——评测集本身是最容易过拟合的地方。
  • Build Your Eval Harness —— 一句话的评测脚手架构建主张。点评：与本节其它材料合读，能看出「harness」这个词正在从 Agent 上下文泄漏到评测语境。
  • Evals: how to know whether an AI system actually works —— 从系统而非模型层面定义「能正常工作」。点评：这个区分很关键——模型跑得好不等于系统能用。
  • How To Use Decision Models for Evals —— Hamel Husain 谈用决策模型来设计评测。点评：把评测标准写成可判定的决策问题，比写成打分量表更可操作。
  • 3 ways to improve agents: simulations, traces, evaluations —— 三条并行的改进路径。点评：simulations 一路值得注意——用生成的环境替代等真实反馈，是把评测成本压下来的关键。
  • How the Claude Code team does code review —— 团队级 code review 实践。点评：当 Agent 产出量上升，人工 review 的对象从「代码」变成「Agent 的改动」。
  • Why your agent reads strangers’ text and can act: which guardrails hold up when the attacker adapts —— 提示注入防护在攻击者自适应时的失效分析。点评：把攻击者当作会进化的对手，比列一份固定的拒绝模式清单更接近现实。
  • Critical thinking when agents do the work —— 谈人在 Agent 产出时的判断角色。点评：与「CI 阻止，Agent 修正」的闭环互为补充——校验之外还需要有人判断该不该信。

三、记忆与上下文：工具很多，问题没变

  • Your agent forgets everything between sessions: which of thirty memory products fixes that —— 横向比较三十余款记忆产品。点评：选项越多，「记忆」的定义越模糊——先问要解决哪类遗忘，比选产品重要。
  • More Memory, Worse Agents: Error Reproduction and Anti-Persistence in LLM Agents —— 论文指出一类反直觉现象：记忆更强反而可能更糟，因为 agent 会复现并固化自己的错误。点评：这是本主题里最值得警惕的一篇，记忆系统需要配遗忘与纠错机制。
  • Memory Is the Moat: How to Build AI Agents That Remember, Without Compromising Security —— 记忆作为护城河与安全的张力。点评：记住得越多，泄露面也越大。
  • How to Build a Second Brain With Claude and Obsidian That Gets Smarter With Every Source You Save —— 个人知识库式的第二大脑方案。点评：这类方案的问题不在检索，而在来源质量没有分层。
  • Git + Wu + Hermes + Ego Lite：我的个人知识库方案 —— 另一位实践者的版本。点评：值得对照的不是工具清单，而是「什么值得被记住」这一层判断。
  • Xudong Han：Agent 一口气改了 Prompt、Skill，还动了执行代码，分数也涨了 —— 自进化实验里，究竟是哪一处改动起了作用。点评：这是自进化研究里最容易糊弄过去的一步——分数涨了不等于知道为什么涨。

四、分布式一致性与共识：细节继续被磨

  • 从 Flexible Paxos 到 Raft：read-write quorum —— 说明 Raft 如何分开配置读 quorum（选举）与写 quorum（日志提交），以及 ReadIndex 与成员变更需要满足的约束。点评：把读路径从提交 quorum 里拆出来，是线性一致读实现的关键一步。
  • OpenRaft 自适应成员变更：新旧 quorum 相交时跳过 joint —— 在新旧配置相交时跳过 joint consensus。点评：joint 配置的常见理由本就是「让两个不相交的集合变相交」，相交时确实多余。
  • 从零手写 Agent —— 每课对照主流 Agent 做法。点评：手写一遍的价值在对照，而不在手写本身。
  • Yac 3.0 发布：常见缓存负载吞吐提升 42% —— Inline 存储、Versioned Snapshot、Memory Epoch 等优化，基准中几何平均吞吐提升 42.3%，小值路径最高 95.4%。点评：数字来自项目自己的基准，注意区分「短 key 路径」和一般负载。

五、模型训练与后训练

  • Training Foundation Models with a Single Algorithm —— 把强化学习重新看作对高分样本的最大似然拟合，从而把生成文本与静态语料同池混合更新。点评：留下的遗产是计算框架的统一——把迭代降维为数据调度，但调度法则仍未解决。
  • Strategist: Evolving Reasoning with Agents —— 把推理策略看作可嵌套的代码蓝图，从旧骨架拼接新策略并实测淘汰。点评：底座极弱时拼接无法无中生有，这个限制作者自己点明了。
  • AI Infra 进阶：3 万字深入理解线性注意力机制 —— 长文讲线性注意力。点评：篇幅长，但线性注意力与 FlashAttention 的取舍是长上下文推理绕不开的问题。
  • A Mathematical Framework for Transformer Circuits —— Transformer 电路的数学框架。点评：机制可解释性的基础文献，配合本期的「写权重」实验读更有意思。
  • 让大模型直接「写权重」，会比训练更容易看懂神经网络吗？—— 这条同期实验：研究者没有训练模型，而是让 Claude 作为自主 coding agent，面对一个空白小型 Transformer，按自然语言任务说明手工设定每一个参数，直接把网络「写出来」。他们一共产出 959 个 weight-space programs，在加法、乘法、排序、奇偶校验、最大公约数等 10 个算法任务上，全部都在 3 次尝试内达到 100% 准确率。点评：作者自己指出 SST-2、MRPC、SNLI 结果受评测设计缺陷影响，SNLI 的 100% 掺入了对评测集的拟合——这正是本期评测主题的活样本。
  • Neural Networks Are Already Clean —— 关于神经元、泛化与电路生态的一个工作假设。点评：可解释性方向的一个新表述框架，值得跟踪。
  • Scaling Discovery Requires Forgetting —— 迭代式 Agent 发现新想法也需要遗忘。点评：与「More Memory, Worse Agents」形成一组有趣的对照——一个讲发现需要忘，一个讲记忆有害。
  • Thinking will become a hobby —— 博客作者对思考这件事在 AI 时代的判断。点评：可与本期的「判断力差距」话题并读。
  • DeepMind 研究员写的《可微编程要素》 同期的书评：跳出「深度学习就是自动微分」的视角，覆盖控制流连续化松弛、隐式方程求导与二阶优化。点评：数学底子够的人能从这本书补上不少工程直觉。

六、算力与产业

  • SemiAnalysis 创始人最新演讲：全球算力告急，英伟达正在成为 AI 时代的「影子银行」 —— 核心观察是 OpenAI 与 Anthropic 正在买空全球 GPU。点评：「影子银行」这个比喻点出了算力从生产资料变成可被撬动的金融头寸。
  • AI 繁荣的三张账单——电、芯片、推理 —— 从成本结构看 AI 繁荣的可持续性。点评：三张账单比「AI 泡沫论」更可证伪，因为每一张都能算。
  • 思科给一个 27 岁工程师无限 token，让他重写 98% 的遗留代码 —— 「我给了他无限的 tokens，因为他要去重构代码。」点评：这是关于 token 与工程效率之间关系的一个极端数据点，但只覆盖重构这一类任务。
  • TwIL-8B：8B 模型开始逼近前沿 同期的主张是竞争点从「更大」转向「更值」。点评：8B 的逼近速度如果持续，小模型在垂直任务上的性价比会持续改善。
  • Deno is joining Cloudflare —— 运行时归属的变化。点评：又一个「基础设施正在被重新归类」的信号，与本站之前谈过的同主题文章可以对照。
  • Yac 3.0、OpenMausBot：Grok Bot 的开源替代品、OpenUI：流式生成界面的新解法 同属「把成熟产品重新实现一遍」的类别。点评：OpenUI 的紧凑语法声称比 JSON 省最多 67% token，这个比例值得自己验一下。

七、工具与效率

  • GitHub - unclebob/ub-mode —— Uncle Bob 为 AI Agent 写的《代码整洁之道》。点评：作者本人的实践比二手解读可靠。
  • 人人都能写出好代码：拆解并实测 Uncle Bob 为 AI Agent 写的《代码整洁之道》ub-mode —— 上述项目的实测拆解。点评：实测文章的价值在于它会失败——只讲优点的测评通常没真跑。
  • 跑完 520 万字和 50 万次判断，做了一个「去 AI 味」Skill —— 点评：52 万次判断这个数字本身就是「规则需要大量样本才能稳定」的证据。
  • unslop：像设计师一样改稿 与 How I Write Papers：先搭提纲，最后写句子 —— 一篇治界面，一篇治写作，方法相同：先定义结构，再填内容。点评：反对边写边想的理由很硬——细节一旦先行，后面往往不得不大改。
  • Anatomy：一个能转能按能读的 Claude skill —— 把想法画成可交互的等距机械图。点评：把「画图」变成可验证的产物，而不是描述需求。
  • motion-prompt：给 AI 补上行业黑话词典 —— 8 个 pack、192 个条目，每条配动态示例与提问示例。点评：卡住往往不是没想法，而是不知道这类动效叫什么。
  • Codync：把电脑里的 AI 编程工具变成一支随叫随到的 bot 小队 —— 把 40 多个已登录的 Agent 统一成可点名的 bot。点评：解决的是「围着某一个聊天窗口打转」这个真实摩擦。
  • databrickslabs/dqx：数据质量校验框架 与 Deno is joining Cloudflare 同期的工程工具。点评：dqx 这类工具的价值在于把「数据对不对」变成 CI 可判定的问题。
  • Rust Style Guide —— Google 起源的开源项目风格指南。点评：值得放进 Agent 可读取的位置，作为自动检查的规则来源。
  • CN 数学知识图谱 —— 1644 个知识点、2403 条先修边、6723 道题。点评：先修边是有价值的那部分数据，它把「学懂 B 之前必须先掌握 A」变成了可计算的图。
  • 算法图谱 os-taxonomy 同类的教学结构化尝试。点评：知识点拓扑比知识点列表有用得多。

八、投资与判断

  • 李录给中国青年投资人的 33 条建议 —— 收件箱转发的完整条目，分能力圈、安全边际、研究方法三部分。点评：这批条目本身不新，但「市场的存在就是专门去发现人性的弱点」和「机会成本变成了现金」这两条今天比写作时更值得重读。
  • 李录哥大最新深度演讲实录：看透周期、AI、中国经济与价值投资 —— 点评：与转发条目对照看，一个是被概括的判断原则，一个是有上下文的完整论述。
  • 投资里最坑人的「金句」，全是因为数学不好 —— 点评：把金句背后的数学补回来，比再收藏十条金句有用。
  • 股市，是一个人人高估自己的地方 —— 点评：作者点出的具体阅读障碍（公告读吃力、商誉、扣非、问询函、关联交易）比「散户高估自己」这个结论有用。
  • 中美股市哪个更赚钱？为什么道指屡创新高，上证指数永远 3000 点？ —— 点评：标题里的问句需要答案而非情绪，动手算一遍指数收益比读评论有效。
  • SemiAnalysis 创始人演讲 的另一面在 搞中转站的人天塌了，Anthropic 这个开源项目有点狠 —— 点评：算力金融化的另一端是成本端被打下来，两件事放一起看比单看更有意思。
  • 公牌的力量 —— 点评：讲的是知道什么时候跟牌、什么时候弃牌，和仓位管理是同一件事。
  • 林园直言投资标准更加苛刻！要有希望！ —— 点评：标题党浓度较高，注意区分表态与论证。

九、认知与表达

  • AI 时代工程师贵在上层抽象 —— 第一性原理、奥卡姆剃刀，让一类问题彻底消失。点评：「让一类问题彻底消失」是比「把一类问题做得更快」更高的目标。
  • 做一款产品带来的进步，胜过读 100 本书 —— 点评：观点本身不新，但「幸福是有心的挑战」这个补充把重点从产出移到了投入方式。
  • Rust Style Guide 与 Anatomy skill 的共同点是把品味外化成可检查的规则。点评：这是本期反复出现的方法论主线。
  • 成年人顶级的社交智慧，它排第一 —— 「挑刺是最廉价的深刻」。点评：一句可执行的观察，胜过十篇泛泛而谈的社交指南。
  • 一个小人物在数据江湖 —— 「21 世纪，物才是上帝，人像工具。」点评：文学化的表达，数据行业的从业者读会有别的共鸣。
  • 人生很短，花好时间的十三条原则 与 乔布斯讲故事的八种手法 —— 玉伯的整理。点评：讲故事的八种手法可以直接当写作清单用。
  • How to become more ambitious: a guide for humans working with models —— Claude 团队成员的翻译与摘录。点评：原文观点是模型能力并不均衡发展，陶哲轩那半句是全文最实用的提醒。
  • The new set of problems for engineers to solve —— 点评：问题重新定义通常比工具升级更重要。
  • 判断，环境，与无限迭代 —— 点评：三个词恰好对应本期三篇长文的共同结构——判断标准、环境设计、迭代闭环。

十、剪藏

  • 入职大厂两个月，我的 AI 开发心得 —— 剪藏于 10 月 10 日。点评：大厂视角的 AI 开发实践，与「个人工作流」类文章形成对照。
  • A modern web app in c —— 剪藏于 10 月 13 日。点评：小语言实现的完整 Web 应用，可作为「够用即止」的案例。
  • Post by @antiAIvo on X —— 剪藏于 10 月 13 日。点评：单条推文，信息量有限，但保留以备后查。
  • blog dds: 2026-10-08 — Thinking will become a hobby —— 剪藏于 10 月 13 日。点评：见第五节，同一篇文章已归入模型与后训练主题。
  • karpathy/nn-zero-to-hero: Neural Networks: Zero to Hero —— 剪藏于 10 月 13 日。点评：配套本期的反向传播与评测主题，是动手学反向传播最合适的一手材料。

十一、补记：11 月 9 日当天新到

以下五条在周报初稿成形后进箱，单独补在这里。

  • 代码验证全景图 · 工具链接版 —— 把代码验证相关的工具与做法整理成一张带链接的全景图。点评：把「怎么验证」做成可查的索引，恰好对上本期反复出现的那条主线——验证机制比多算一遍更值得投入。
  • 【译文】你的编程智能体，让你成了管理者（By Addy Osmani） —— Osmani 把与 Agent 协作逐条翻译成管理学动作：先给它自我验证的手段、交代它看不到的上下文、同一件事纠正两次就写进 CLAUDE.md 或做成 skill、连续两次纠正失败就换会话重写提示词、可以委派工作但不交出判断。点评：最有价值的是那些可执行阈值（「纠正两次」而非「适度干预」），这类数字才是管理类建议能被照做的原因。
  • How to Cut Your Agent Bill by 90% With Jev Engineering and Kimi K3 —— 思路是先把 Agent 循环里那些「不是在创造、只是在判断」的小决策（下一步调哪个工具、这条来源相不相关、测试过没过、命令安不安全）拆出来，交给专为此训练的 System One 模型（Jev）回答，把难案例路由给大模型。点评：与本轮 token 优化的几条材料是同一个方向——把便宜任务从贵模型上摘出去，收益来自路由而不是压缩。
  • 我把 5 个 Skill 做成了插件，才发现 DeepSeek Harness 的野心这么大 —— 从插件作者视角写生态定位：官方把 Harness 类比为「Agent 时代的操作系统」，插件与官方内置功能并存，靠用户选择优胜劣汰。点评：这个类比同时是承诺和免责声明——生态开放，但标准与兼容性成本会落到插件作者身上。
  • 谈一谈游戏和《影之刃零》 —— 一篇与本期技术主线无关的游戏随笔（作者自述前两篇被平台和谐，这次聊闲篇）。点评：与技术素材无关，保留在此仅为记录来源，阅读时可跳过。

下期预告

素材里最值得继续跟进的三个方向：评测集本身的过拟合问题（本期有多篇材料从不同角度碰到它）、长程任务的失败可读性（Ralph Loop 循环与状态机方案都在这条线上）、记忆系统的收益与代价（More Memory, Worse Agents 与记忆产品横评互相印证）。
