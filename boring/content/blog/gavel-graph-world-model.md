## 一句话总结

GAVEL 就像给大语言模型（LLM）配备了一张**动态的"因果地图"**：每做一个动作之前，先在地图上"预演"一遍后果，发现不对就自动修复，不用每次都去问模型。这样做出来的机器人规划，成功率从 41% 暴涨到 92%，而且推理成本更低。

---

## 背景：LLM 做机器人规划的三大噩梦

想象你让一个机器人帮你收拾房间："先把桌上的书放进书架，然后把花瓶放到窗台，最后把脏衣服扔进洗衣机。"这句话听起来简单，但对 LLM 来说，它要面对三个几乎无解的难题：

### 1. 物理约束违反：机器人不知道"物理定律"

LLM 没有真正的身体，它不知道：

- 花瓶是玻璃的，不能用力捏
- 书比书架的隔层宽，硬塞会坏
- 机器人的手臂伸不到某个角度

结果是：LLM 生成的规划**物理上不可执行**，但它自己不知道。

### 2. 无法恢复：错了就错了

假设机器人已经**把花瓶打碎了**，LLM 还接着执行原计划的后续步骤。它不知道世界已经变了，还在按"花瓶还在"的前提继续调度。

就像一个没有记忆的人，每次做完动作就**忘记自己做了什么**，后面每一步都建立在错误的世界状态之上。

### 3. 物体跟丢：不知道东西在哪

在真实家庭环境中，很多东西你**看不到**（抽屉里、沙发底下、柜子后面）。LLM 不知道：

- 钥匙可能在卧室，也可能在客厅
- 我有 60% 的把握它在卧室床头柜里
- 但我不知道钥匙到底在不在鞋盒里

LLM 经常**编造**物体位置（幻觉），或者**忘记**自己已经移动过某个东西。

## 核心方法：图世界模型

GAVEL 的核心思想很简单：**不要让 LLM 在脑子里模拟所有事情，而是用一个外部的"图"来记录世界的状态和变化规律。**

### 什么是一张"会预测后果的图"？

把这张图想象成一个**数字化的房间地图**：

```text
┌─────────────────────────────────────────┐
│  图世界模型（Graph World Model）          │
├─────────────────────────────────────────┤
│                                         │
│  📦 物体节点                             │
│    ├── 位置: 厨房台面（60%）/ 洗碗机（40%）│
│    ├── 状态: 干净 / 脏                   │
│    └── 属性: 玻璃材质 / 陶瓷材质          │
│                                         │
│  🔗 关系边                               │
│    ├── 书 "在" → 书架第3层               │
│    ├── 花瓶 "放在" → 窗台                │
│    └── 脏衣服 "在" → 卧室地板            │
│                                         │
│  ⚙️ 动作规则                             │
│    ├── 拿起(X): 需要 X可见 且 手臂够得着  │
│    ├── 放下(X,Y): X当前在手中            │
│    └── 打开(X): X是容器 且 X是关闭的     │
│                                         │
│  📊 概率信念                             │
│    └── 对于不可见的物体，维护一个概率分布 │
│                                         │
└─────────────────────────────────────────┘
```

**关键点**：这张图是**独立于 LLM 的**，LLM 只负责"说我要做什么"，而这张图负责"验证这么做对不对"。

### 三步走：预测 → 检测 → 修复

#### 第一步：预演（Pre-execution Prediction）

当 LLM 说："机器人去拿花瓶，放到窗台上。"

GAVEL **不急着执行**，而是先在图上模拟：

```text
LLM 的指令：
  "拿起花瓶 → 放到窗台"

图世界模型的预演：
  Step 1: 检查"花瓶"在哪里？
    → 查图：当前位置 = 客厅茶几
    → 状态：可见 ✓

  Step 2: 检查"拿起"动作的前置条件
    → 花瓶可见 ✓
    → 机器人手臂够得着茶几高度 ✓
    → 预测结果：花瓶从茶几 → 机器人的手

  Step 3: 检查"放到窗台"的前置条件
    → 窗台高度? 1.2米
    → 机器人手臂最大伸展角度? 可达 ✓
    → 预测结果：花瓶从机器人的手 → 窗台

  Step 4: 更新图状态
    → 花瓶位置更新为"窗台"
    → 标注置信度：高（因为所有条件都满足）
```

**全程不需要调用 LLM**，图本身就能推演。

#### 第二步：违规检测（Violation Detection）

如果预演中发现问题，图就会"报警"：

```text
❌ 检测到违规：

LLM 说："把玻璃花瓶放进微波炉加热"

图世界模型预演：
  Step 1: 检查"玻璃"属性
    → 材质: 玻璃 ❌
    → 动作: "加热"
    → 后果预测: 花瓶会碎 / 爆炸 💥

  → 违规类型: 物理约束违反
  → 错误来源: 直接可从图的属性推导，不需要问 LLM
```

这就是 GAVEL 名字的精髓——**G**raph **A**ction **V**erification before **E**xecution and **L**earning。

#### 第三步：自修复（Self-Repair）

检测到错误后，GAVEL 不是立刻让 LLM 重新规划，而是**先尝试自己修**：

```text
检测到错误：花瓶（玻璃材质）不能放进微波炉

GAVEL 自修复尝试：
  方案 A: 把"加热"改成"常温放置"
    → 图验证: 可行，花瓶完好 ✓
    → 执行这个替代方案
```

## 实验效果

| 场景 | 成功率 |
|------|--------|
| 纯 LLM 规划 | 41% |
| **GAVEL（图世界模型 + LLM）** | **92%** |
| 提升幅度 | **+51 个百分点** |

更关键的是，GAVEL 不仅成功率更高，**推理成本还更低**——因为很多违规检测和修复不需要调用 LLM，图本身就能搞定。

## 不只是机器人：通用 Agent 的状态追踪

GAVEL 的思路可以推广到所有长周期 Agent 场景：

```text
传统软件 Agent 的问题：
  → 转账后账户A余额变化，LLM 不知道
  → 后续购买时用错误的余额做判断

GAVEL 风格的解决：
  → 用图记录每个账户的实时余额
  → 转账后自动扣减/增加对应金额
  → 购买前先查图的当前余额，不够就拒绝或提示
```

**核心思想**：无论软件 Agent 还是机器人 Agent，都需要一种**独立于 LLM 的状态追踪机制**，让 LLM 每次做决策时都有一个"真实世界状态"的参考，而不是靠记忆（幻觉的主要来源）。

---

## 总结

GAVEL 的核心贡献是引入了**图世界模型（Graph World Model）**作为 LLM 的外部验证层：

1. **图负责"懂物理"**：记录物体属性和动作规则，检测物理上不可行的动作
2. **图负责"记状态"**：每步执行后更新状态，解决"状态跟丢"问题
3. **图负责"自动修"**：简单错误图自己修，只有语义问题才问 LLM
4. **图负责"算概率"**：对不可见物体维护概率分布，支持有依据的猜测

这张"因果地图"让 LLM 从"盲目执行"变成了"有地图导航的智能执行"，是长周期 Agent 规划领域的一个实用且有效的突破。
