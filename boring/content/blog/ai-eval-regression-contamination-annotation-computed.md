## 一、笔记的骨架：25 题里挑三道

这三道题的共同点是——**答案里都有一个「拍出来的数字」，而这个数字能不能站住，取决于三个可计算的量**。

**Q14 回归测试套件**：答案是「一组**固定不变**的测试用例 + 评分逻辑，用于检测 prompt/模型/架构改动是否引入退化」，并分三层：Layer 1 **确定性快照**（输入→输出快照比对，适用 classification、routing）、Layer 2 **Pairwise 比较**（旧版本 vs 新版本，用 LLM judge 判断哪个更好，阈值「≥70% 新版本不显著更差」）、Layer 3 **打分阈值**（每个用例独立打分，较基线下降 >5% 即回归）。构建步骤里有两个数字：**从生产 trace 采样 200–500 条**、**至少 50 条人工标注**其余 weak-label。

**Q16 基准污染**：定义是「训练数据中意外或故意包含 benchmark 测试样本，导致模型见过答案而非真会做」；给了污染程度光谱（无污染 / 轻度 / 中度 / 严重 / 完全泄漏）与**三大污染源**（训练数据混入、微调泄漏、RAG 污染）、**五种检测方法**（N-gram 重叠、Embedding 相似度、Membership Inference、Held-out 评估、动态 benchmark）。

**Q25 冷启动建评测集**：没有标注、没有专家时，用**六种策略**组合：Synthetic Generation、Weak Supervision、Self-Consistency、Expert Seeding、Bootstrap from Public、Production Mining。

## 二、增量一：回归阈值与用例数是一对

笔记说「较基线下降 >5% 即回归」。这个 5% 会不会天天误报？取决于用例数量与单用例分数波动——把它算出来：

```python
"""回归测试套件：用例数量 n 决定回归阈值能不能不误报。

用笔记给的量：200-500 条用例、>=50 条人工标注、pairwise 阈值 70%、分数较基线下降 >5% 判回归。
只依赖标准库；输出确定性。
"""
import math

CASES_MAX = 500
SCORE_SD = 0.10        # 单用例打分的标准差（估）
REGRESSION_TH = 0.05   # 笔记给的阈值：较基线下降 >5% 判回归
DAILY_RUNS = 20        # 每天 CI 跑多少次（估）
JUDGE_LATENCY_S = 0.5  # 一次 judge 调用延迟（估）
PRICE_PER_CALL = 0.002 # 每次 judge 调用成本（美元，估）

print("回归判定：分数较基线下降 > %.0f%% 即判回归（笔记口径）" % (REGRESSION_TH * 100))
print("问题：这个阈值会不会「天天误报」？取决于用例数量 n 与单用例分数波动。")
print()
print("%-8s %14s %14s %18s %20s" % ("用例数 n", "均值标准误", "阈值/标准误", "单次跑假回归率", "每天 20 次跑"))
for n in (20, 50, 100, 200, 500):
    se = SCORE_SD / math.sqrt(n)
    z = REGRESSION_TH / se
    # 单尾正态尾概率（用 erf 计算）
    false_rate = 0.5 * math.erfc(z / math.sqrt(2))
    print("%-8d %14.4f %14.2f %17.2f%% %19.2f 次" % (n, se, z, false_rate * 100, false_rate * DAILY_RUNS))
print()
print("反解：要控制「每天假回归 <= 0.1 次」，n 至少要多少？")
target = 0.1 / DAILY_RUNS
z_need = 3.0   # 单尾 0.1% 大致的 z 值
n_need = (SCORE_SD / (REGRESSION_TH / z_need)) ** 2
print("  目标假回归率 %.4f/次 -> 约需 z >= %.1f -> n >= %d 条用例（按单用例 sd=%.2f）"
      % (target, z_need, int(n_need), SCORE_SD))
print("  => 5% 阈值在 n=20 时每次跑就有 1.27% 假回归率（每天 20 次 ≈ 0.25 次），")
print("     n>=50 后基本不误报 —— 所以笔记的「200-500 条」买到的主要是**覆盖率与代表性**，")
print("     而不是阈值稳定性（后者 50 条就够）。")
print()
print("三层各自的成本（每次 CI 跑一次）：")
for name, calls_per_case, calls in (
    ("Layer 1 确定性快照", 0, 0),
    ("Layer 2 pairwise（抽 20%）", 1, int(CASES_MAX * 0.2)),
    ("Layer 3 打分（全量）", 1, CASES_MAX),
):
    total = calls_per_case * calls
    secs = total * JUDGE_LATENCY_S
    cost = total * PRICE_PER_CALL
    print("  %-26s %4d 次 judge -> 串行 %6.1f 秒、并发 100 需 %5.1f 秒、$%.2f/次"
          % (name, total, secs, secs / 100, cost))
daily = (int(CASES_MAX * 0.2) + CASES_MAX) * DAILY_RUNS
print()
print("  每天 %d 次 CI -> %s 次 judge 调用/天 -> $%.2f/天、$%.0f/月"
      % (DAILY_RUNS, format(daily, ","), daily * PRICE_PER_CALL, daily * PRICE_PER_CALL * 30))
print()
print("判据：")
print("  - **阈值与用例数是一对**：sd=0.10 时 5%% 阈值要 n>=%d 才不天天误报；n=20 时阈值只有 %.1f sigma。" % (int(n_need), REGRESSION_TH / (SCORE_SD / math.sqrt(20))))
print("  - **pairwise 比绝对打分更稳**：同一批用例上比新旧版本，用例间的方差大部分抵消，")
print("    差值的标准误远小于各自分数的标准误 —— 所以 layer 2 的 70% 阈值可以比 layer 3 的 5% 更宽松。")
print("  - **贵的层少跑、便宜的层多跑**：确定性快照免费全量；打分全量但可夜间跑；pairwise 只在 PR 上抽样。")
print("  - 成本账要显式算：%s 次 judge/天、$%.2f/天 —— 不算就不知道该不该把 LLM judge 放进 CI。" % (format(daily, ","), daily * PRICE_PER_CALL))
```

三处结论：

**第一，5% 这个阈值只有配合足够的用例才成立。** 单用例分数标准差取 0.10 时，用例数 n 的均值标准误是 `0.10/√n`：n=20 → 0.0224，5% 阈值只相当于 **2.24σ**，单次跑的假回归率 **1.27%**；按每天 20 次 CI 算，就是**每天 0.25 次假报警**（每三四天一次）。n≥50 后假回归率降到 0.02% 以下，基本不误报。反解：**要控制「每天假回归 ≤ 0.1 次」，n ≥ 36**。

**第二，所以笔记里「200–500 条」买到的不是阈值稳定性，而是覆盖率与代表性。** 阈值这件事 50 条就够；多出来的 150–450 条买的是**场景覆盖**（happy path + edge + adversarial 都要有）与**代表性**（从生产 trace 采样，而不是自己编）。**判据：先把 n 和阈值配对，再谈套件大小**——用 20 条用例配 5% 阈值，得到的是一个天天报警、没人看的门禁。

**第三，三层的成本必须显式算，因为 LLM judge 不便宜。** 每次 CI 跑一次：Layer 1 快照 **0 次 judge**（免费全量）；Layer 2 pairwise 抽 20%（100 次 judge，串行 50 秒、并发 100 需 0.5 秒、**$0.20**）；Layer 3 全量打分（500 次 judge，串行 250 秒、并发 100 需 2.5 秒、**$1.00**）。每天 20 次 CI → **12,000 次 judge 调用/天、$24/天、$720/月**。判据：**贵的层少跑、便宜的层多跑**——快照全量每次跑，打分全量但放夜间，pairwise 只在 PR 上抽样。

顺带一条方法上的差别：**pairwise 比绝对打分更稳**。同一批用例上比新旧版本，用例之间的方差大部分抵消，差值的标准误远小于各自分数的标准误——所以 Layer 2 的「70% 不显著更差」可以比 Layer 3 的「下降 >5%」宽松得多。**两个阈值不能互相套用。**

## 三、增量二：污染检测是二分类，阈值决定漏检与误报

笔记给的 Membership Inference 思路是「模型对样本的 perplexity 是否异常低」。把它形式化成二分类：

```python
"""基准污染检测：perplexity 阈值 -> 检出率与误报率，以及污染让分数虚高多少。

用笔记给的机制：membership inference（训练集样本 perplexity 异常低）+ held-out 子集。
只依赖标准库；输出确定性。
"""
import math

# perplexity 是右偏的，用对数正态建模（log PPL ~ Normal）
LOG_MU_CONTAM = 0.20   # 被污染样本（模型见过）log PPL 的均值（估）
LOG_SD_CONTAM = 0.12
LOG_MU_CLEAN = 1.30    # 干净样本 log PPL 的均值（估）
LOG_SD_CLEAN = 0.45
N_BENCH = 1000    # benchmark 样本数
CONTAM_RATE = 0.05  # benchmark 中被污染的比例（估）


def norm_cdf(x):
    return 0.5 * (1.0 + math.erf(x / math.sqrt(2)))


def lognormal_cdf(x, mu, sd):
    """P(PPL <= x)，其中 log PPL ~ N(mu, sd)"""
    if x <= 0:
        return 0.0
    return norm_cdf((math.log(x) - mu) / sd)


print("污染检测 = 二分类：污染样本的 perplexity 分布 vs 干净样本的分布")
print("  污染: log PPL ~ N(%.2f, %.2f)（中位数 %.2f）| 干净: log PPL ~ N(%.2f, %.2f)（中位数 %.2f）"
      % (LOG_MU_CONTAM, LOG_SD_CONTAM, math.exp(LOG_MU_CONTAM),
         LOG_MU_CLEAN, LOG_SD_CLEAN, math.exp(LOG_MU_CLEAN)))
print()
print("%-10s %14s %14s %14s" % ("阈值 tau", "检出率 TPR", "误报率 FPR", "Youden J"))
best = None
for i in range(1, 71):
    tau = 0.6 + i * 0.05
    tpr = lognormal_cdf(tau, LOG_MU_CONTAM, LOG_SD_CONTAM)
    fpr = lognormal_cdf(tau, LOG_MU_CLEAN, LOG_SD_CLEAN)
    j = tpr - fpr
    if best is None or j > best[3]:
        best = (tau, tpr, fpr, j)
    if i % 5 == 0:
        print("%-10.2f %13.1f%% %13.1f%% %14.3f" % (tau, tpr * 100, fpr * 100, j))
print()
print("最佳阈值 tau = %.2f -> 检出率 %.1f%%、误报率 %.1f%%（Youden J = %.3f）" % (best[0], best[1] * 100, best[2] * 100, best[3]))
print()
print("这个检测的漏检与误报在 benchmark 上的实际代价：")
for label, rate, kind in (("污染样本被当成干净（漏检）", best[2], "fpr"),
                           ("干净样本被当成污染（误报）", best[1], "tpr")):
    pass
missed = N_BENCH * CONTAM_RATE * (1 - best[1])      # 污染样本中 PPL 高于阈值 -> 漏检
false_flag = N_BENCH * (1 - CONTAM_RATE) * best[2]   # 干净样本中 PPL 低于阈值 -> 误报
print("  benchmark 有 %d 条、污染率 %.0f%%（%d 条）" % (N_BENCH, CONTAM_RATE * 100, int(N_BENCH * CONTAM_RATE)))
print("  漏检：%d 条污染样本被判干净 -> 这 %d 条的分数继续被当成有效成绩" % (int(missed), int(missed)))
print("  误报：%d 条干净样本被判污染 -> 以为有污染其实没有，需要人工复核" % int(false_flag))
print()
print("污染让分数虚高多少：若污染样本与测试集同分布，污染率 p 直接抬高分母上的正确率")
for p in (0.01, 0.05, 0.10, 0.30):
    print("  污染率 %4.0f%% -> 分数最多虚高 %4.1f 个百分点（真实力扣掉 p 才是可信区间）" % (p * 100, p * 100))
print()
print("判据：")
print("  - **污染检测本质是二分类，阈值决定漏检与误报**：本模型最优 tau=%.2f 时检出 %.1f%%、误报 %.1f%%；" % (best[0], best[1] * 100, best[2] * 100))
print("    漏检的代价是「分数继续虚高」，误报的代价是「白查一轮」——所以该偏向检出率。")
print("  - **污染率的置信区间要扣掉污染**：污染率 5% 的 benchmark，分数最多虚高 5 个百分点；")
print("    报成绩时必须给出「扣掉污染率后的下界」，而不是单点分数。")
print("  - held-out 子集（笔记给的五种方法之一）是唯一不依赖阈值的办法：")
print("    用训练前就存在的子集做 clean 基线，两条线之差就是污染贡献。")
```

```text
判据：
  - **污染检测本质是二分类，阈值决定漏检与误报**：本模型最优 tau=1.65 时检出 99.4%、误报 3.8%；
    漏检的代价是「分数继续虚高」，误报的代价是「白查一轮」——所以该偏向检出率。
  - **污染率的置信区间要扣掉污染**：污染率 5% 的 benchmark，分数最多虚高 5 个百分点；
    报成绩时必须给出「扣掉污染率后的下界」，而不是单点分数。
  - held-out 子集（笔记给的五种方法之一）是唯一不依赖阈值的办法：
    用训练前就存在的子集做 clean 基线，两条线之差就是污染贡献。
```

三处结论：

**第一，污染检测天然是一个 ROC 问题，阈值不能拍。** perplexity 是右偏的，用对数正态建模：被污染样本（模型见过）log PPL ~ N(0.20, 0.12)（中位数 1.22），干净样本 ~ N(1.30, 0.45)（中位数 3.67）。扫阈值：**最优 τ=1.65 时检出率 99.4%、误报率 3.8%**（Youden J=0.956）；阈值放到 4.10 则检出 100% 但误报 **59.7%**——一半的干净样本被冤枉。

**第二，两种错误的代价不对称，所以阈值该偏向检出。** 在 1000 条 benchmark、污染率 5% 的场景：最优阈值下**漏检 0 条**、**误报 35 条**。漏检的代价是「这 50 条污染样本的成绩继续被当成有效分数」；误报的代价是「白查一轮、让工程师去复核 35 条其实干净的数据」。**判据：误报贵在人力，漏检贵在结论失真**——所以宁可多查一轮，也不要让污染样本混进成绩。

**第三，也是最实用的一条：污染率直接是分数虚高的上界。** 若污染样本与测试集同分布，污染率 p 就直接抬高了正确率：p=1% → 分数最多虚高 1 个点；p=5% → 5 个点；p=10% → 10 个点。**判据：报 benchmark 成绩时必须给出「扣掉污染率后的下界」，而不是一个单点分数**——一个宣称 72% 的模型，在 5% 污染下真实水平可能只有 67%。而笔记给的 **held-out 评估**是唯一不依赖阈值的办法：用训练前就存在的子集做 clean 基线，**两条线之差就是污染贡献**。

## 四、增量三：评测集要的是覆盖率，不是条数

笔记的冷启动策略里，Production Mining（从生产数据挖掘正确 case）成本最低。问题是从生产 trace 里挑哪 200 条来标：

```python
"""冷启动评测集：同样的标注预算，分层采样比随机采样覆盖多少场景。

只依赖标准库；输出确定性（自写 LCG 初始化 k-means++，固定迭代次数）。
"""
import math

N = 100_000        # 生产 trace 总量
CLUSTERS = 200     # 聚类数（估）
BUDGET = 200       # 人工标注预算（条）
LABEL_MINUTES = 10  # 每条人工标注耗时（分钟，估）

MASK = (1 << 64) - 1


def mix64(x):
    x = (x + 0x9E3779B97F4A7C15) & MASK
    z = x
    z = ((z ^ (z >> 30)) * 0xBF58476D1CE4E5B9) & MASK
    z = ((z ^ (z >> 27)) * 0x94D049BB133111EB) & MASK
    return z ^ (z >> 31)


class LCG:
    def __init__(self, seed):
        self.s = seed & MASK

    def next(self):
        self.s = (self.s * 6364136223846793005 + 1442695040888963407) & MASK
        return self.s

    def rand(self):
        return (self.next() >> 11) / float(1 << 53)


def make_data():
    """造 12 维特征、20 个簇中心的合成 trace 集合（确定性）。"""
    rng = LCG(20261127)
    centers = [[rng.rand() * 10 for _ in range(12)] for _ in range(CLUSTERS)]
    sizes = []
    total = 0
    for i in range(CLUSTERS):
        w = 1.0 / (i + 1) ** 0.7          # 长尾：靠前的簇大
        sizes.append(w)
        total += w
    sizes = [s / total * N for s in sizes]
    pts = []
    for i, c in enumerate(centers):
        cnt = int(sizes[i])
        for _ in range(cnt):
            pts.append([c[d] + (rng.rand() - 0.5) * 0.9 for d in range(12)])
    return pts, centers, sizes


def dist2(a, b):
    return sum((a[d] - b[d]) ** 2 for d in range(len(a)))


def kmeans(pts, k, iters=8):
    rng = LCG(777)
    centers = [list(pts[int(rng.rand() * len(pts))]) for _ in range(k)]
    assign = [0] * len(pts)
    for _ in range(iters):
        for i, p in enumerate(pts):
            best_j, best_d = 0, None
            for j, c in enumerate(centers):
                d = dist2(p, c)
                if best_d is None or d < best_d:
                    best_d, best_j = d, j
            assign[i] = best_j
        sums = [[0.0] * 12 for _ in range(k)]
        cnt = [0] * k
        for i, p in enumerate(pts):
            j = assign[i]
            cnt[j] += 1
            for d in range(12):
                sums[j][d] += p[d]
        for j in range(k):
            if cnt[j]:
                centers[j] = [sums[j][d] / cnt[j] for d in range(12)]
    return assign, centers, cnt


# 用已知簇中心生成数据：簇 id 即语义分组（等价于 k-means 的极限情形），
# 这样把「采样策略」这一个变量单独隔离出来，不掺入聚类算法的误差。
rng = LCG(20261127)
CLUSTERS = 200
weights = [1.0 / (i + 1) ** 0.7 for i in range(CLUSTERS)]
total_w = sum(weights)
sizes = [int(w / total_w * N) for w in weights]
labels = []
for c in range(CLUSTERS):
    labels.extend([c] * sizes[c])
rng2 = LCG(4242)
for _ in range(len(labels)):
    rng2.next()
nonempty = sum(1 for s in sizes if s > 0)

print("合成 %s 条 trace、%d 个簇（长尾分布：最大簇 %s 条、最小簇 %d 条）"
      % (format(len(labels), ","), CLUSTERS, format(max(sizes), ","), min(sizes)))
print()
print("标注预算固定为 %d 条，两种选法：" % BUDGET)
strat = min(BUDGET, nonempty)
print("  分层采样（每簇 1 条）：覆盖 %d 个簇（%.0f%%）" % (strat, 100.0 * strat / CLUSTERS))
expected_random = CLUSTERS * (1 - math.pow(1 - 1.0 / CLUSTERS, BUDGET))
print("  随机采样 %d 条：期望覆盖 %.0f 个簇（%.0f%%）" % (BUDGET, expected_random, 100.0 * expected_random / CLUSTERS))
print("  => 分层比随机多覆盖 %.0f%% 的场景（同一个人工预算）" % (100.0 * (strat - expected_random) / expected_random))
print()
big = sorted(range(CLUSTERS), key=lambda i: -sizes[i])[:20]
print("长尾覆盖（最大的 20 个簇，占 %s 条 trace）：" % format(int(sum(sizes[i] for i in big)), ","))
random_hit = 20 * (1 - math.pow(1 - 1.0 / CLUSTERS, BUDGET))
print("  随机采样 %d 条时，期望命中这 20 个簇中的 %.1f 个；分层采样必中 20 个" % (BUDGET, random_hit))
print()
print("标注成本账：")
print("  %d 条 x %d 分钟 = %.1f 小时 = %.1f 人天（按 8 小时）" % (BUDGET, LABEL_MINUTES, BUDGET * LABEL_MINUTES / 60, BUDGET * LABEL_MINUTES / 60 / 8))
print("  笔记给的建议是「>= 50 条人工标注，其余 weak-label」-> 人工 %d 条 = %.1f 小时，占预算 %.0f%%" % (
    50, 50 * LABEL_MINUTES / 60, 100.0 * 50 / BUDGET))
print()
print("判据：")
print("  - **同样的标注预算，分层采样覆盖的场景多 %.0f%%** —— 覆盖率是评测集可信度的第一因子，" % (100.0 * (strat - expected_random) / expected_random))
print("    而样本条数不是（条数只影响统计精度，不影响覆盖面）。")
print("  - **长尾场景正是随机采样最容易漏掉的**：最大的 20 个簇随机只命中 %.1f 个，分层必中 20 个。" % random_hit)
print("  - **成本账要显式算**：200 条 x 10 分钟 = 33 小时 = 4.2 人天；而笔记建议的人工只标 50 条（8.3 小时），")
print("    其余用 weak label —— 这是用「标注噪声」换「标注预算」，要按风险分层分配。")
```

输出：

三处结论：

**第一，同样的标注预算，分层采样覆盖的场景多 58%。** 10 万条生产 trace、200 个簇（长尾：最大簇 7,368 条、最小簇 180 条）、标注预算 200 条：**每簇 1 条的分层采样覆盖 200 个簇（100%）**，而随机采样 200 条期望只覆盖 **127 个（63%）**。

**第二，长尾场景正是随机采样最容易漏掉的。** 最大的 20 个簇合计占 40,304 条 trace（40% 的流量）：随机采样期望只命中其中 **12.7 个**，分层采样**必中 20 个**。判据：**条数只影响统计精度，覆盖面才影响可信度**——评测集漏掉一个高频长尾场景，比少 50 条样本严重得多。

## 五、把三个模型套回本章（判据清单）

1. **回归阈值与用例数必须配对**：sd=0.10 时 5% 阈值要求 n ≥ 36 才不天天误报（n=20 时每天 0.25 次假报警）。200–500 条买的是覆盖率，不是阈值稳定性。
2. **pairwise 与绝对打分的阈值不能互相套用**：前者因方差抵消更稳，70% 与 5% 是两套口径。
3. **judge 成本要显式算**：500 条全量打分 = 500 次 judge；每天 20 次 CI = 12,000 次 = $24/天。分层跑法（快照全量、打分夜间、pairwise 抽样）是省钱也是省时间。
4. **污染检测是二分类**：最优 τ=1.65 时检出 99.4%、误报 3.8%；τ 放到 4.10 则误报 59.7%。
5. **误报贵在人力、漏检贵在结论失真** → 阈值偏向检出率（最优阈值下漏检 0 条、误报 35 条）。
6. **污染率是分数虚高的上界**：5% 污染 → 分数最多虚高 5 个点；报成绩必须给扣掉污染后的下界。
7. **held-out 子集是不依赖阈值的那条路**：两条线之差就是污染贡献。
8. **评测集先看覆盖率再看条数**：同样 200 条，分层覆盖 200 簇、随机只覆盖 127 簇（+58%）。
9. **长尾最容易被随机采样漏掉**：最大的 20 个簇（40% 流量）随机只命中 12.7 个，分层必中 20 个。
10. **标注预算按重要度分层花**：人工标 50 条（8.3 小时）覆盖高风险，其余 150 条用弱标注换预算。

## 七、这三个模型判不了什么

- **单用例分数 sd=0.10、judge 延迟 500 ms、单价 $0.002、perplexity 分布参数、簇数 200、标注 10 分钟/条都是估的**。真实 judge 的评分噪声更大（同一输出两次打分能差 0.1 以上），这会**放大**误报率——所以实际需要的 n 比本模型算出的 36 更多。
- **没算 pairwise 判定的不对称性**：讲义里「新版本不显著更差」的判定本身有噪声，而 pairwise 的方差抵消只在**同一批评分**成立；换成不同模型做 judge，方差抵消就不成立。
- **没算污染的分布前提**。「污染率 p 直接抬高分 p 个点」依赖「污染样本与测试集同分布」——若污染只是**同类型不同题目**（轻度污染），虚高幅度远小于 p。**污染程度光谱里的五档不能用同一个公式。**
- **没算 held-out 子集的构造难度**：笔记说它是不依赖阈值的办法，但「训练前就存在的子集」需要历史数据快照与严格的时间切分，运营成本高；而且切分一旦有泄漏，held-out 也会被污染。
- **三个模型都没碰多轮对话与事实一致性的评测**（笔记 Q22/Q23）：那里的难点是「标注单位是什么」（一轮？一轮里的一句？），本文的覆盖率与条数框架只能部分套用。

## FAQ（八、常见问题）

**5% 的回归阈值能直接用吗？** 取决于用例数。单用例分数 sd=0.10 时，n=20 的均值标准误是 0.0224，5% 只相当于 **2.24σ**，单次假回归率 **1.27%**，每天 20 次 CI 就是 **0.25 次假报警**；n≥50 后基本不误报。**反解：每天假回归 ≤0.1 次需要 n ≥ 36。**

**回归套件要多大？** 阈值稳定 50 条就够；笔记建议的 200–500 条买的是**覆盖率与代表性**（从生产 trace 采样，含 happy/edge/adversarial）。**先配对阈值与 n，再决定套件大小**——20 条配 5% 阈值会得到一个没人看的门禁。

**把 LLM judge 放进 CI 要花多少钱？** 500 条全量打分 = 500 次 judge 调用；按每天 20 次 CI、每次 $1.00 算，是 **$24/天、$720/月**；pairwise 抽 20% 则是 $0.20/次。分层跑法（快照全量免费、打分全量放夜间、pairwise 只在 PR 上抽样）能把成本压下来。**不算这笔账就不知道该不该把 judge 放进 CI。**

**怎么检测基准污染？** 核心是 membership inference：被污染样本的 perplexity 异常低。把两者当二分类并扫阈值（perplexity 右偏，用对数正态建模）：最优 τ=1.65 时**检出 99.4%、误报 3.8%**；阈值放到 4.10 会让 **59.7%** 的干净样本被冤枉。误报贵在人力、漏检贵在结论失真，所以阈值应偏向检出率。

**污染会让分数虚高多少？** 若污染样本与测试集同分布，污染率 p 就是虚高上界：5% 污染 → 分数最多虚高 **5 个点**。所以报成绩要给**扣掉污染率后的下界**，而不是单点数字。**唯一不依赖阈值的方法是 held-out**：用训练前就存在的子集做 clean 基线，两条线之差就是污染贡献。

**没有标注怎么建评测集？** 六种策略组合（合成、弱监督、自一致性、专家种子、公开数据、生产挖掘），但**选哪 200 条来标**更关键：10 万条 trace、200 个簇、预算 200 条时，**每簇 1 条的分层采样覆盖 200 个簇，随机采样只覆盖 127 个（+58%）**；最大的 20 个簇（40% 流量）随机只命中 12.7 个。**条数影响精度，覆盖面影响可信度。**
