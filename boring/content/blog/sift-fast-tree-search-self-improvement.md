## 一句话总结

让 LLM 担任"裁判"来评判候选解的优劣，用一棵轻量搜索树来组织自我改进过程——不需要反复跑完整基准测试，就能找到更强的模型。

---

## 背景：老方法的痛点在哪

### DGM 怎么做的

DGM（Direct Gradient Model）这类方法做自我改进时，核心循环是：

1. 让模型生成一批候选解（patch）
2. 在完整基准测试上逐一评估每个候选解
3. 用评估结果训练模型，让它更倾向于生成高分解
4. 重复以上步骤

这个流程听起来合理，但问题出在**评估环节**。

### 评估的成本有多高

想象你要选出一位"年度最佳员工"，但每次投票都要让所有候选人做一整套述职报告——耗时、耗力、耗资源。

基准测试也是一样：

- 跑一次完整评估可能需要几十个 CPU 节点运行数小时
- 如果你生成了 80 个候选解，就得跑 80 次完整评估
- 每次评估还要花钱调用 API

DGM 跑了 80 个节点，效果是 30.7%。**成本高，但收益并不惊艳。**

---

## 核心方法：SIFT 的三步走

### 第一步：LLM 裁判做两两比较

SIFT 不让 LLM 给候选解打绝对分数（"这个解打 8 分"），而是让它做**两两比较**（"A 和 B 哪个好"）。

类比：选秀节目里，评委不需要让每个选手都完整表演一首歌再打分——让他们同台 PK，观众一眼就能看出高下。

让人或 LLM 做绝对评分（"这个解打几分"）往往不稳定，但做两两比较（"A 和 B 哪个好"）更可靠，也更容易校准。

### 第二步：Bradley-Terry 模型——从胜负记录算实力分

LLM 裁判会给出大量"A 赢 B"、"B 输 A"的胜负记录。怎么从这些记录里算出每个候选解的真实实力？

SIFT 用了**正则化 Bradley-Terry 模型**。

这个模型的思路很朴素：

- 如果 A 赢 B 的次数多于 B 赢 A 的次数，说明 A 比 B 强
- 引入正则化，防止某些候选解因为场次太少而排名虚高
- 最终给每个候选解算出一个"实力分数"

### 第三步：解耦树搜索——按实力分布采样

得到实力分数后，怎么生成下一代候选解？

SIFT 用了一种**按实力加权采样**的树搜索：

- 分数高的候选解，被选为"父节点"的概率更大
- 搜索树不断扩展，每轮生成新的候选解
- 完整基准测试只用在最少数的"最有希望的节点"上

类比：像一个积分淘汰赛，先用预选赛筛选出前 10 名，再让这 10 名选手跑正式比赛——大幅节省预选成本。

### 关键设计：解耦

搜索树和评估是"解耦"的——搜索树只负责组织候选解的结构和采样策略，不直接参与评估。这让系统更稳定，也更容易调优。

## 实验效果

### Polyglot 基准

| 方法 | 性能 | 消耗 |
|------|------|------|
| DGM | 30.7% | 80 节点 |
| **SIFT** | **35.1%** | **<50 CPU 小时** |

SIFT 比 DGM 高出 4.4 个百分点，同时计算成本还更低——不到 50 CPU 小时就能跑完。

### TerminalBench 基准

用高质量裁判（gpt-5.4-high）时，SIFT 从 29.2% 的起点找到了 36.7% 的代理。

但有趣的发现是：换一个差一点的裁判（gpt-5），虽然也找到了 34.5% 的代理，但把一个**更弱的候选解排在了前面**。

这直接说明了裁判质量的重要性。

### Qwen3-30B 实验

花了 224 CPU 小时和 34 美元 API 费用——大约是 DGM 基线的**十分之一**成本。

## 为什么裁判质量决定结果

这是论文最核心的洞察：

> "如果你在跑自我改进循环，裁判值得和搜索算法一样多的关注。"

原因很直观：

- 裁判的判断是整个系统的信号源
- 如果裁判判断错了，即使搜索算法再精巧，也是在优化错误的目标
- 好的裁判能区分细微的质量差异，引导搜索走向正确方向
- 差的裁判会把弱的候选解误判为强，让整个过程南辕北辙

类比：GPS 决定了导航的终点，裁判决定了自我改进的方向。方向错了，跑得越快错得越远。

## 对工程师的意义

### 1. 评估是瓶颈，评估优化是杠杆

自我改进系统的瓶颈往往不在"生成"环节，而在"评估"环节。先想清楚怎么高效评估，比急着优化生成更重要。

### 2. 两两比较 > 绝对评分

让人或 LLM 做绝对评分（"这个解打几分"）往往不稳定，但做两两比较（"A 和 B 哪个好"）更可靠，也更容易校准。

### 3. 引入搜索结构是有价值的

没有结构的随机采样效率很低。一棵组织良好的搜索树能更好地利用评估结果，把好钢用在刀刃上。

### 4. 裁判是系统的灵魂

选择和调优裁判，可能是整个系统最重要的工程决策。你用什么信号来指导优化，决定了系统最终会变成什么样。

---

## 总结

SIFT 展示了一条务实但深刻的路径：与其拼命跑更多基准，不如先用轻量级裁判做大量两两比较，用树搜索组织候选解的结构，最后只对最有希望的候选解跑完整评估。

**裁判即方向，方向决定结局。**
