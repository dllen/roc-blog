本期周报覆盖 10 月 7 日到 11 月 9 日的收件箱、归档文章与剪藏，共 217 条原始条目，以下按主题归类摘录其中有独立信息量的部分。每条给出链接、一段摘要和一句点评；只做导读，不搬运原文。

## 一、Agent 架构：从脚手架走向状态机

这一期数量最多的主题。素材共同指向一个方向：**给 Agent 搭脚手架（harness）的做法正在让位于给 Agent 设计状态与验证机制。**

- [Super-agent 设计探索：迈向更自主的 Agent 系统](https://mp.weixin.qq.com/s/zoS7GlReWPhfCjENGxXCdg) —— DeepSeek Harness 团队对更自主 Agent 系统的架构思路探讨。点评：文章自己声明这是架构思路而非产品功能介绍，这类自我限定反而值得信任。
- [评 DeepSeek Super-Agent 探索：为什么小秘书遇上大工程就拉胯？](https://mp.weixin.qq.com/s/Jfsnkl-uEcX08bkTEXjJRA) —— 作者的判断是超级助理缺的不是更多 Session，而是别的什么东西。点评：这类批评比原方案自述更有信息量，因为它指出了缺口而非复述优点。
- [从长程 Agent 到 Super-agent，解锁更多场景](https://mp.weixin.qq.com/s/O6NdGGHP_rKAnH9PKrt6iQ) —— 阿里云 AgentCore 视角的演进梳理：对话到动手，简单任务到长程任务，再到跨实体任务。点评：三段式划分给「长程」这个词提供了可操作的定义。
- [Agent State Machines: Building Deterministic Scaffolding for Agents](https://x.com/josharosen/status/2117687393213932003) —— Josh Rosen 提出用显式状态机为 Agent 提供确定性脚手架。点评：「确定性」是对当前脚手架范式最直接的反驳——预测式接口的每一步都在赌。
- [Loops and Graphs: how to stop babysitting agents and only approve the last step](https://x.com/hanakoxbt/status/2091515787366306154) —— 用循环与图取代人工盯梢，只在最后一步审批。点评：把审批点从每轮移到终点，是把「信任」问题换成「可回滚」问题的思路。
- [Graph Engineering: how to build the agent system that replaced loops](https://x.com/0xshoopy/status/2085383231554171098) —— 同一位作者的进一步主张。点评：与前一条正好构成一组对照，可看成一个命题的正反面。
- [从长程 Agent 到 Super-agent，解锁更多场景](https://mp.weixin.qq.com/s/O6NdGGHP_rKAnH9PKrt6iQ) 与 [小秘书遇上大工程](https://mp.weixin.qq.com/s/Jfsnkl-uEcX08bkTEXjJRA) 两篇的共同结论：**会话数量不是扩展性的解法**，任务分解与状态管理才是。
- [深度解析 Codex Harness 架构及其全新上下文压缩记忆体系的设计思路](https://mp.weixin.qq.com/s/IM-zakQ9Bnog54NdYiJSqA) —— 基于 Codex CLI 开源源码剖析 Harness 与记忆机制。点评：源码可查的技术梳理比产品宣传页可靠得多。
- [Agent 的工具箱，正在收缩成一个 exec](https://mp.weixin.qq.com/s/4XgAlbTE-ZfjO29twc8yFw) 一类的观点在同期反复出现：不再逐个给模型点工具，而是给一个受控沙箱让它写代码调用工具。点评：Code Mode 减少了工具描述的 token 成本，但也把「选错工具」换成了「写错代码」。
- [ThinkRail：JetBrains 开源的智能体 IDE](https://github.com/JetBrains/thinkrail) —— 围绕 pi 编码智能体，用 git-worktree 隔离并行任务的工作区。点评：worktree 隔离 + 规范文档图谱，是本篇主线在工作区侧的具体化。
- [Personal Agent 落地思考：主动性从哪来，又卡在哪？](https://mp.weixin.qq.com/s/c5k2iwYh1O1OLA8ULf5X_A) —— Qoder 团队关于 Agent 主动性的思考。点评：主动性的难点在于授权边界，而非能力边界。
- [交付周期从 51 天缩短到 14 天，多 Agent 协作产品自进化背后的组织重构](https://mp.weixin.qq.com/s/4ys53fyi5x0zG7AHofK9HA) —— Agentic SOC 产品的组织改造记录。点评：交付周期缩短四分之三的同时，团队结构也变了——这部分往往被一句「效率提升」盖过。

## 二、评测与验证：这期最一致的主题

多个来源不约而同地指向同一个位置：模型能力不是瓶颈，**判断产出对不对**才是。

- [Automating eval design and hillclimbing with Claude](https://claude.dev/blog/automating-eval-design-and-hillclimbing/) —— Anthropic 讲评测设计与自动爬坡的基本原则。点评：标题里的 without fooling yourself 是重点——评测集本身是最容易过拟合的地方。
- [Build Your Eval Harness](https://x.com/tonycueva/status/2115089591824744957) —— 一句话的评测脚手架构建主张。点评：与本节其它材料合读，能看出「harness」这个词正在从 Agent 上下文泄漏到评测语境。
- [Evals: how to know whether an AI system actually works](https://x.com/sermakarevich/status/2106453816757354947) —— 从系统而非模型层面定义「能正常工作」。点评：这个区分很关键——模型跑得好不等于系统能用。
- [How To Use Decision Models for Evals](https://x.com/hamelhusain/status/2112588257104216294) —— Hamel Husain 谈用决策模型来设计评测。点评：把评测标准写成可判定的决策问题，比写成打分量表更可操作。
- [3 ways to improve agents: simulations, traces, evaluations](https://x.com/ashpreetbedi/status/2116203130266501560) —— 三条并行的改进路径。点评：simulations 一路值得注意——用生成的环境替代等真实反馈，是把评测成本压下来的关键。
- [How the Claude Code team does code review](https://x.com/addyosmani/status/2114604912520921136) —— 团队级 code review 实践。点评：当 Agent 产出量上升，人工 review 的对象从「代码」变成「Agent 的改动」。
- [Why your agent reads strangers' text and can act: which guardrails hold up when the attacker adapts](https://x.com/sermakarevich/status/2115801259173151024) —— 提示注入防护在攻击者自适应时的失效分析。点评：把攻击者当作会进化的对手，比列一份固定的拒绝模式清单更接近现实。
- [Critical thinking when agents do the work](https://x.com/addyosmani/status/2117512471930167377) —— 谈人在 Agent 产出时的判断角色。点评：与「CI 阻止，Agent 修正」的闭环互为补充——校验之外还需要有人判断该不该信。

## 三、记忆与上下文：工具很多，问题没变

- [Your agent forgets everything between sessions: which of thirty memory products fixes that](https://x.com/sermakarevich/status/2115087554877776113) —— 横向比较三十余款记忆产品。点评：选项越多，「记忆」的定义越模糊——先问要解决哪类遗忘，比选产品重要。
- [More Memory, Worse Agents: Error Reproduction and Anti-Persistence in LLM Agents](https://arxiv.org/abs/2610.27406) —— 论文指出一类反直觉现象：记忆更强反而可能更糟，因为 agent 会复现并固化自己的错误。点评：这是本主题里最值得警惕的一篇，记忆系统需要配遗忘与纠错机制。
- [Memory Is the Moat: How to Build AI Agents That Remember, Without Compromising Security](https://x.com/_ar9av/status/2114770422948659499) —— 记忆作为护城河与安全的张力。点评：记住得越多，泄露面也越大。
- [How to Build a Second Brain With Claude and Obsidian That Gets Smarter With Every Source You Save](https://x.com/imryven/status/2115046979659055476) —— 个人知识库式的第二大脑方案。点评：这类方案的问题不在检索，而在来源质量没有分层。
- [Git + Wu + Hermes + Ego Lite：我的个人知识库方案](https://x.com/realchendahuang/status/2118545092986413146) —— 另一位实践者的版本。点评：值得对照的不是工具清单，而是「什么值得被记住」这一层判断。
- [Xudong Han：Agent 一口气改了 Prompt、Skill，还动了执行代码，分数也涨了](https://x.com/xudong07452910/status/2113428439630020858) —— 自进化实验里，究竟是哪一处改动起了作用。点评：这是自进化研究里最容易糊弄过去的一步——分数涨了不等于知道为什么涨。

## 四、分布式一致性与共识：细节继续被磨

- [从 Flexible Paxos 到 Raft：read-write quorum](https://mp.weixin.qq.com/s/umOr-ofrjAUvTmSB1RiJ7Q) —— 说明 Raft 如何分开配置读 quorum（选举）与写 quorum（日志提交），以及 ReadIndex 与成员变更需要满足的约束。点评：把读路径从提交 quorum 里拆出来，是线性一致读实现的关键一步。
- [OpenRaft 自适应成员变更：新旧 quorum 相交时跳过 joint](https://mp.weixin.qq.com/s/44CSHGwS2AAV6U1HeloNkQ) —— 在新旧配置相交时跳过 joint consensus。点评：joint 配置的常见理由本就是「让两个不相交的集合变相交」，相交时确实多余。
- [从零手写 Agent](https://namiai.tech/agent/?v=1) —— 每课对照主流 Agent 做法。点评：手写一遍的价值在对照，而不在手写本身。
- [Yac 3.0 发布：常见缓存负载吞吐提升 42%](https://www.laruence.com/2026/10/19/7656.html) —— Inline 存储、Versioned Snapshot、Memory Epoch 等优化，基准中几何平均吞吐提升 42.3%，小值路径最高 95.4%。点评：数字来自项目自己的基准，注意区分「短 key 路径」和一般负载。

## 五、模型训练与后训练

- [Training Foundation Models with a Single Algorithm](https://arxiv.org/abs/2610.40564) —— 把强化学习重新看作对高分样本的最大似然拟合，从而把生成文本与静态语料同池混合更新。点评：留下的遗产是计算框架的统一——把迭代降维为数据调度，但调度法则仍未解决。
- [Strategist: Evolving Reasoning with Agents](https://arxiv.org/abs/2611.03618) —— 把推理策略看作可嵌套的代码蓝图，从旧骨架拼接新策略并实测淘汰。点评：底座极弱时拼接无法无中生有，这个限制作者自己点明了。
- [AI Infra 进阶：3 万字深入理解线性注意力机制](https://mp.weixin.qq.com/s/O0_v8wz4iHxbkDLENy7EPg) —— 长文讲线性注意力。点评：篇幅长，但线性注意力与 FlashAttention 的取舍是长上下文推理绕不开的问题。
- [A Mathematical Framework for Transformer Circuits](https://transformer-circuits.pub/2021/framework/index.html) —— Transformer 电路的数学框架。点评：机制可解释性的基础文献，配合本期的「写权重」实验读更有意思。
- 让大模型直接「写权重」，会比训练更容易看懂神经网络吗？—— 这条同期实验：研究者没有训练模型，而是让 Claude 作为自主 coding agent，面对一个空白小型 Transformer，按自然语言任务说明手工设定每一个参数，直接把网络「写出来」。他们一共产出 959 个 weight-space programs，在加法、乘法、排序、奇偶校验、最大公约数等 10 个算法任务上，全部都在 3 次尝试内达到 100% 准确率。点评：作者自己指出 SST-2、MRPC、SNLI 结果受评测设计缺陷影响，SNLI 的 100% 掺入了对评测集的拟合——这正是本期评测主题的活样本。
- [Neural Networks Are Already Clean](https://already-clean.goodfire.com/) —— 关于神经元、泛化与电路生态的一个工作假设。点评：可解释性方向的一个新表述框架，值得跟踪。
- [Scaling Discovery Requires Forgetting](https://arxivb.org/abs/2610.20563) —— 迭代式 Agent 发现新想法也需要遗忘。点评：与「More Memory, Worse Agents」形成一组有趣的对照——一个讲发现需要忘，一个讲记忆有害。
- [Thinking will become a hobby](https://www.spinellis.gr/blog/20261008/?li261008) —— 博客作者对思考这件事在 AI 时代的判断。点评：可与本期的「判断力差距」话题并读。
- [DeepMind 研究员写的《可微编程要素》](https://diffprog.github.io) 同期的书评：跳出「深度学习就是自动微分」的视角，覆盖控制流连续化松弛、隐式方程求导与二阶优化。点评：数学底子够的人能从这本书补上不少工程直觉。

## 六、算力与产业

- [SemiAnalysis 创始人最新演讲：全球算力告急，英伟达正在成为 AI 时代的「影子银行」](https://mp.weixin.qq.com/s/msGRwgi1IFi34rThqrdErQ) —— 核心观察是 OpenAI 与 Anthropic 正在买空全球 GPU。点评：「影子银行」这个比喻点出了算力从生产资料变成可被撬动的金融头寸。
- [AI 繁荣的三张账单——电、芯片、推理](https://x.com/clorissignal/status/2110159825330225169) —— 从成本结构看 AI 繁荣的可持续性。点评：三张账单比「AI 泡沫论」更可证伪，因为每一张都能算。
- [思科给一个 27 岁工程师无限 token，让他重写 98% 的遗留代码](https://mp.weixin.qq.com/s/19Irnk9DG1LVcAqOBq9KFQ) —— 「我给了他无限的 tokens，因为他要去重构代码。」点评：这是关于 token 与工程效率之间关系的一个极端数据点，但只覆盖重构这一类任务。
- [TwIL-8B：8B 模型开始逼近前沿](https://huggingface.co/webAI-Official/TwIL-8B) 同期的主张是竞争点从「更大」转向「更值」。点评：8B 的逼近速度如果持续，小模型在垂直任务上的性价比会持续改善。
- [Deno is joining Cloudflare](https://deno.com/blog/cloudflare) —— 运行时归属的变化。点评：又一个「基础设施正在被重新归类」的信号，与本站之前谈过的同主题文章可以对照。
- [Yac 3.0](https://www.laruence.com/2026/10/19/7656.html)、[OpenMausBot：Grok Bot 的开源替代品](https://mp.weixin.qq.com/s/tD4Arm8lTAfpwfT9skH6XA)、[OpenUI：流式生成界面的新解法](https://github.com/thesysdev/openui) 同属「把成熟产品重新实现一遍」的类别。点评：OpenUI 的紧凑语法声称比 JSON 省最多 67% token，这个比例值得自己验一下。

## 七、工具与效率

- [GitHub - unclebob/ub-mode](https://github.com/unclebob/ub-mode) —— Uncle Bob 为 AI Agent 写的《代码整洁之道》。点评：作者本人的实践比二手解读可靠。
- [人人都能写出好代码：拆解并实测 Uncle Bob 为 AI Agent 写的《代码整洁之道》ub-mode](https://x.com/longhaiqwe123/status/2115286893663498696) —— 上述项目的实测拆解。点评：实测文章的价值在于它会失败——只讲优点的测评通常没真跑。
- [跑完 520 万字和 50 万次判断，做了一个「去 AI 味」Skill](https://x.com/lieflat_3/status/2118355780474937831) —— 点评：52 万次判断这个数字本身就是「规则需要大量样本才能稳定」的证据。
- [unslop：像设计师一样改稿](https://github.com/heydamir/unslop) 与 [How I Write Papers：先搭提纲，最后写句子](https://thoughtforms.life/wp-content/uploads/2026/10/add-to-Substack-post.pdf) —— 一篇治界面，一篇治写作，方法相同：先定义结构，再填内容。点评：反对边写边想的理由很硬——细节一旦先行，后面往往不得不大改。
- [Anatomy：一个能转能按能读的 Claude skill](https://skills.wheresryan.sh/anatomy) —— 把想法画成可交互的等距机械图。点评：把「画图」变成可验证的产物，而不是描述需求。
- [motion-prompt：给 AI 补上行业黑话词典](https://github.com/showheyohtaki/motion-prompt) —— 8 个 pack、192 个条目，每条配动态示例与提问示例。点评：卡住往往不是没想法，而是不知道这类动效叫什么。
- [Codync：把电脑里的 AI 编程工具变成一支随叫随到的 bot 小队](https://github.com/leepokai/Codync) —— 把 40 多个已登录的 Agent 统一成可点名的 bot。点评：解决的是「围着某一个聊天窗口打转」这个真实摩擦。
- [databrickslabs/dqx：数据质量校验框架](https://github.com/databrickslabs/dqx) 与 [Deno is joining Cloudflare](https://deno.com/blog/cloudflare) 同期的工程工具。点评：dqx 这类工具的价值在于把「数据对不对」变成 CI 可判定的问题。
- [Rust Style Guide](https://google.github.io/styleguide/rustguide.html) —— Google 起源的开源项目风格指南。点评：值得放进 Agent 可读取的位置，作为自动检查的规则来源。
- [CN 数学知识图谱](https://github.com/xiaoyang111222/cn-math-taxonomy) —— 1644 个知识点、2403 条先修边、6723 道题。点评：先修边是有价值的那部分数据，它把「学懂 B 之前必须先掌握 A」变成了可计算的图。
- [算法图谱 os-taxonomy](https://github.com/withmarbleapp/os-taxonomy) 同类的教学结构化尝试。点评：知识点拓扑比知识点列表有用得多。

## 八、投资与判断

- [李录给中国青年投资人的 33 条建议](https://b23.tv/TxJh83V) —— 收件箱转发的完整条目，分能力圈、安全边际、研究方法三部分。点评：这批条目本身不新，但「市场的存在就是专门去发现人性的弱点」和「机会成本变成了现金」这两条今天比写作时更值得重读。
- [李录哥大最新深度演讲实录：看透周期、AI、中国经济与价值投资](https://mp.weixin.qq.com/s/7LjsjDCnfPUSZHr0wB6krA) —— 点评：与转发条目对照看，一个是被概括的判断原则，一个是有上下文的完整论述。
