Agent 记忆不是一个功能，是一组互斥的取舍。事实会变时，是覆盖旧值还是让旧值过期？需要跨三份文档拼答案时，是多轮检索还是图上一步跳？记忆占了多少 token、拖慢多少延迟？这三个问题在不同论文里有完全不同的答案，而且**每篇论文都只在自己的指标上赢**。

这篇按「你的问题是什么」组织，给出选型路径，并把每个方案的实测数字回到论文原文核对（2026-11-24 抓取）。顺带说明一件容易踩的事：这些分数不能横向比。

## 一、先认问题，不是先认论文

四类问题对应四条完全不同的技术路线：

| 你的问题 | 对应机制 | 代表方案 | 前提条件 |
|---|---|---|---|
| 用户改了地址、偏好，旧事实怎么办 | 双时态建模，事实有有效期而非被覆盖 | Zep / Graphiti | 事实真的会变，且历史需可回溯 |
| 问题需要跨多份文档串联才能答 | 知识图谱 + 图上扩散检索 | HippoRAG | 答案真需要多跳，单点检索不够 |
| 记忆要长期在线，但 token 与延迟不能爆 | 增量抽取-更新管线，只留关键事实 | Mem0 | 上下文装不下全部历史 |
| Agent 反复犯同样的错，要复用解法 | 技能库，把成功路径固化成可执行代码 | Voyager | 任务会重复出现 |

先说清两条前提，否则后面的数字会被误读。

**这四个方案不是在同一张榜单上比出来的。** Zep 评测的是 MemGPT 提出的 DMR 基准，Mem0 评测的是 LOCOMO，A-MEM 评测的是 LoCoMo 与 DialSim。每篇论文都只在自己的评测集上比较，第二节到第五节的数字因此不能横向放在一起看——第六节专门讲这个坑。

**全量上下文始终是一个被低估的基线。** 在 Zep 的 DMR 上，全量上下文拿到 94.4%，几乎追平 Zep 的 94.8%；在 Mem0 的 LOCOMO 上，全量上下文约 73%，高于 Mem0 的 67% 与 Mem0g 的 68.44%。记忆系统的价值来自「用更少的钱拿到接近的分数」，而不是「分数最高」。只有上表末列的前提成立时，它才必然占优。

早期范式是 Generative Agents 提出的记忆流（memory stream）：把每次经历用自然语言存下来，检索时按近因性（recency）、重要性（importance）、相关性（relevance）加权召回，其中近因性按「距上次检索的游戏内小时数」做指数衰减。这套机制今天仍然在用，但它是**只增不减**的——事实变了，旧记录还在。

## 二、事实会变：Zep 的双时态是把「失效」变成一等公民

传统 RAG 遇到事实变更只有两种处理：覆盖，或新旧并存。Zep（arXiv:2501.13956）选了第三条路：**给事实加有效期，让旧事实优雅地过期而不是被抹掉**。

它的建模有两个时间轴。论文原文的表述是：时间线 T 表示事件的时序顺序，时间线 T' 表示数据入库的事务顺序。对应地，每条事实带四个时间戳——t'_created 与 t'_expired 属于事务时间轴（记录事实何时进入系统、何时被判定失效），t_valid 与 t_invalid 属于有效时间轴（记录事实本身在什么时间段成立）。底层引擎 Graphiti 还做了「边失效」（edge invalidation）：新事实进来时，沿事务时间轴优先用新信息判定旧边是否失效。

以「用户搬家」为例：旧地址在 t_valid 上被截断，新地址重新起算有效期，而系统仍能回答「他之前住哪」。这一点在需要审计和回溯的企业场景里不是加分项，是前提。

**实测分数**（DMR 基准，500 段多会话对话，每段 5 个会话最多 12 条消息）：

| 记忆模型 | gpt-4-turbo | gpt-4o-mini |
|---|---|---|
| 递归摘要 | 35.3% | — |
| 会话摘要 | 78.6% | 88.0% |
| MemGPT | 93.4% | 无法复现（原文：方法细节不足） |
| 全量上下文 | 94.4% | 98.0% |
| **Zep** | **94.8%** | **98.2%** |

论文自己写明了两件容易被略过的事。一是「全量上下文」这个 baseline 在 gpt-4-turbo 下拿到 94.4%，已经略微超过 MemGPT 报告的 93.4%——Zep 相对它只领先 0.4 个百分点。二是在 gpt-4o-mini 下无法复现 MemGPT 的结果，原因是 MemGPT 论文的方法细节不足以支撑复现。

另外注意这两项评测都由 Zep 团队自己执行，且 Zep 论文采用 CC BY-NC-SA 4.0 协议，引用其数据需遵守非商业条款。

**Zep 也有它不擅长的**：单会话助手类问题（single-session-assistant）上，gpt-4o 下降 17.7%、gpt-4o-mini 下降 9.06%。论文把这归为「需要进一步研究与工程工作」的方向，而不是隐去。

## 三、多跳串联：HippoRAG 借海马体索引做一步扩散

传统 RAG 处理多跳要「检索 → 拼接 → 再检索」地循环，每跳都要过一次 LLM。HippoRAG（arXiv:2405.14831，NeurIPS 2024）换了个思路：受人类海马体索引理论启发，把 LLM、知识图谱和 Personalized PageRank 组合起来，检索时从 query 定位种子节点，然后在图上做扩散，**一次完成跨文档的多跳关联**。

第二版（arXiv:2502.14802，ICML 2025）的论文标题是《From RAG to Memory: Non-Parametric Continual Learning for Large Language Models》——注意它不叫「HippoRAG 2」，叫这个名字的只是论文里对自己框架的称呼。它的增量在于修了一个上一代的问题：给 RAG 加知识图谱会改善 sense-making 和联想性检索，但**在基础事实记忆任务上反而明显掉到标准 RAG 之下**，第二版把这个非预期劣化拉了回来。

选型含义：如果你要串的是「分散在不同文档里的关联事实」，图扩散比多轮 RAG 少几次 LLM 调用；如果问题就是单点事实检索，原始 RAG 可能更省。

## 四、成本与延迟：Mem0 的取舍是「少存」

Mem0（arXiv:2504.19413）的思路是记忆层不存全部对话，只在多轮会话里动态抽取、整合、检索关键信息。它的图增强变体在原文里写作 Mem0g。

**实测分数**（LOCOMO 基准，LLM-as-Judge 的 J 分）：

| 方案 | J 分 | p95 延迟 |
|---|---|---|
| 全量上下文（约 26,000 token） | 约 73% | 基准 |
| 最强 RAG baseline | 约 61% | — |
| **Mem0** | **67%** | 约 1.44 秒 |
| **Mem0g** | **68.44%** | 2.590 秒 |

论文自述的三条结论：Mem0 相对 OpenAI baseline 在 J 分上相对提升 26%；p95 延迟比全量上下文低 91%，token 成本节省超过 90%；Mem0g 比基础 Mem0 高约 2 个百分点。

这里必须诚实指出一个容易被标题掩盖的事实：**全量上下文的 J 分仍然最高（约 73%），比 Mem0 的 67% 高。** Mem0 赢的是「用约四分之一的 token 拿到接近的分数」，不是「分数最高」。论文给出的分项收益是相对最优 baseline 的单跳 +5%、时序 +11%、多跳 +7%。

另一个细节解释了为什么时间戳重要：OpenAI baseline 在多跳问题上得分低于 15%，主要原因不是检索能力弱，而是生成的记忆里大多缺时间戳。

## 五、技能复用：Voyager 与 Reflexion 的两种失败与成功

前三个方案解决的是「记住什么」，这两个解决的是「记住怎么做」。

Voyager（arXiv:2305.16291，TMLR 2023）是第一个在 Minecraft 里做开放式终身学习的 LLM Agent，三个组件：自动课程（最大化探索）、持续增长的可执行代码技能库、迭代提示机制（把环境反馈、执行错误、自我校验写进下一次尝试）。技能是可组合的，所以能力会滚雪球式增长。作者强调技能是「时间上延展、可解释、可组合」的。

Reflexion（arXiv:2303.11366，NeurIPS 2023）走的是另一半：不更新权重，用语言反馈强化 Agent。Agent 口头反思任务反馈，把反思文本存在情景记忆缓冲区里，影响下一次尝试。它能吃标量值也能吃自由文本，反馈既可以来自外部也可以是内部模拟的。

对比很清楚：

| | 写入触发 | 存的是什么 | 适用 |
|---|---|---|---|
| Reflexion | 失败后 | 自然语言教训 | 试错型任务，要记住「哪里错了」 |
| Voyager | 成功后 | 可执行代码 | 重复型任务，要记住「怎么做对」 |

一个偏故障复盘，一个偏技能沉淀。

## 六、为什么这些分数不能横向比

这是选型时最容易出错的地方。上面四组数字看起来都在比「谁更强」，但它们连量纲都不是一回事：

- **Zep 的 DMR 94.8%** 是检索准确率（Deep Memory Retrieval），任务是从多会话对话里找回指定信息；
- **Mem0 的 J 分 67%** 是 LLM-as-Judge 打分，任务是对话问答；
- **A-MEM 的 F1 3.45** 出自 DialSim 数据集，论文同时报告了 LoCoMo 上按五类问题（单跳、多跳、时序、开放域、对抗）分列的另一组 F1；
- **LongMemEval 的 30% 下降**是相对商用助手与长上下文模型的衰减幅度，不是绝对分。

**跨论文比大小之前，先确认数据集、指标、基线实现和底座模型四项一致。** 有两个具体例子：

其一，同一个 A-MEM，两个数字来自两处不同的实验。Mem0 论文报告「A-mem 在 J 分上落后超过 25 个百分点」，但那张表的数据来自 LOCOMO，且表注写明 A-Mem\* 是 **Mem0 团队把温度设为 0 重跑 A-Mem 得到的 J 分**，不是引用 A-MEM 原文的数值。这与 A-MEM 自己报的「DialSim 上 F1 3.45、领先 LoCoMo 的 2.55」既不同数据集也不同指标，两句话不构成矛盾，但也说明它们不能互相印证。

其二，同样在 LOCOMO 上，Mem0 论文报告 A-Mem 的 search latency 中位数为 0.668s、总响应延迟中位 1.410s，原因是它的记忆库更大、检索开销更高——这是可以直接对比的成本数字，而不是需要跨表换算的分数。想比 A-MEM 和 Mem0 谁强，先看你要比的是准确率还是成本；两个维度上它们各有胜负。

还有一个更隐蔽的坑：**口径细节不会在每篇论文里完整复述**。LoCoMo 原文在问答任务上明确采用 F1 partial match（把预测与标准答案都归一化后做词袋级部分匹配）；A-MEM 论文的附录只给了 precision/recall/F1 的通式，说「F1 用于衡量预测答案与参考答案之间的 exact matches」，并未复述 partial match 这一实现细节。两篇论文都在报 F1，但读者若假定口径一致，就会读出并不存在的结论。

评测基准本身的分工也要记住：

- **LongMemEval**（arXiv:2410.10813，ICLR 2025）考五项能力：信息抽取、跨会话推理、时序推理、知识更新、拒答。500 道题嵌在可自由扩展的会话历史里。论文报告商用聊天助手和长上下文模型在持续交互中掉约 30% 准确率——这条数字比任何单点分数都更能说明问题：不是模型记不住，是记住了没法用对。
- **LoCoMo**（arXiv:2402.17753，ACL 2024）提供超长对话。按原文附录的统计：50 段对话，平均每段 19.3 个会话、每会话 15.8 轮、每段约 9,209 token；QA 基准共 7,512 题（单跳 2,705 / 多跳 1,104 / 时序 1,547 / 开放域 285 / 对抗 1,871）。论文摘要里另一组口径是「平均 300 轮、9K token、最多 35 个会话」，两处说法并存，看的时候注意区分。

## 七、什么情况下你不需要记忆系统

一个必须说出口的判断：如果你的 Agent 只需要在一次会话内工作，或者记忆的总量能一次性塞进上下文窗口，那么上面所有复杂度都是净损失。Zep 论文的 DMR 表提供了一个参照：在这个基准上，全量上下文 baseline 拿到 94.4%，几乎追平 Zep 的 94.8%。

记忆系统的收益出现在**上下文装不下、事实会变、或者需要跨会话复用**这三种情况之一。都不满足时，最省事的方案是把历史放文件里让 Agent 自己读——这也是 Anthropic 在上下文工程一文里主张的路线：基于文件系统的扁平透明记忆（渐进式披露的知识库、由 Agent 自己检索和维护）在编码类场景往往比黑盒向量库更可控也更好调试。可对照已发的[上下文工程](/blog/context-engineering-instruction-and-material/)与[会成长的个人助手](/blog/growing-personal-assistant-lab1/)两篇，它们讲的是同一枚硬币的另一半：材料怎么进上下文，以及被纠正后怎么落盘。

## 八、读哪些论文

按目的选，不必全读：

| 你的处境 | 先读 |
|---|---|
| 刚接触，想建立术语框架 | CoALA（arXiv:2309.02427，TMLR）——把记忆拆成工作记忆、情景记忆、语义记忆、程序记忆四类，是目前引用最广的理论框架 |
| 要动手实现一个 | MemGPT（arXiv:2310.08560）——虚拟内存类比，Agent 用工具调用自主换入换出上下文，是 Letta 的前身 |
| 关心领域全景 | 《Memory in the Age of AI Agents》（arXiv:2512.13564）——按 forms–functions–dynamics 三维梳理；以及《From Storage to Experience》（arXiv:2605.06716，ACL 2026 Findings）——把演进总结为存储、反思、经验三阶段 |
| 要选型 | 本文第二节到第六节 |

工程博客四条路线各自代表一种取向：[Lilian Weng 的 Agent 入门](https://lilianweng.github.io/posts/2023-06-23-agent/)讲清了感觉记忆、短期上下文学习与长期检索的映射；[LangChain 的 Memory for Agents](https://www.langchain.com/blog/memory-for-agents)与 [LangMem](https://langchain-ai.github.io/langmem/)把 CoALA 理论落成代码模式，并区分 Hot Path（对话中同步更新，延迟高但实时）与 Background（后台异步整理）；[Letta 的 Agent Memory](https://www.letta.com/blog/agent-memory/)与 [Sleep-Time Compute](https://www.letta.com/blog/sleep-time-compute/)提出利用 Agent 空闲时间在后台重组去重记忆，而不只在提问时推理。

开源实现：[letta-ai/letta](https://github.com/letta-ai/letta)、[getzep/graphiti](https://github.com/getzep/graphiti)、[mem0ai/mem0](https://github.com/mem0ai/mem0)、[Shichun-Liu/Agent-Memory-Paper-List](https://github.com/Shichun-Liu/Agent-Memory-Paper-List)（社区维护的论文清单库）。

## 九、几条边界

上面每个方案都有论文自陈的局限，这里汇总成选型时该问的问题：

- Zep 在单会话助手类问题上准确率下降（gpt-4o 上 17.7%），并非全场景占优；其 DMR 相对全量上下文的领先幅度只有 0.4 个百分点（gpt-4-turbo）。
- Mem0 在 LOCOMO 上的 J 分低于全量上下文，赢在 token 与延迟；跨方案比较时它的绝对分并不领先。
- HippoRAG 的图结构在基础事实检索上不必然优于原始 RAG，第二版才把这个劣化修回来。
- A-MEM 的优势建立在「选择性 top-k 检索」上——它靠少检索换 token（每次记忆操作约 1,200 token，论文给出的同实验下 LoCoMo 与 MemGPT 两种方法的用量是 16,900 token；该组成本数字出自论文的 DialSim 实验段），召回范围被主动收窄。
- 所有跨论文比较都受底座模型与提示词差异影响，A-MEM 在六个基础模型上做了评测，Mem0 只报了部分模型，报数时要看清。
